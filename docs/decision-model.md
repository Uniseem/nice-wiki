# 决策模型（Jev）全站架构与文档索引

决策模型（OpenRouter 上的 TypeSafe Jev，`typesafe/jev-1.14`）只回答带类型的题目：是非题给“是”的概率，单选题给每个选项的概率，打分题给有序等级。它不写一个字，输入便宜、输出免费。文本模型能写，但慢且贵。本文定下两者的分工、各环节怎么用决策模型，以及文档索引（index.md）的生成、更新和压缩方式。

## 分工原则

- **先判断，再动笔**：凡是“要不要做、选哪个、是不是”的问题都先问决策模型；只有真正需要生成文字时才调文本模型。决策模型像前台调度，文本模型是后台专家。
- **一次多问**：同一份状态里的多道题放进一次调用，不按题拆开。
- **拿不准就保守**：每道题按概率阈值取用，达不到阈值时按“需要做、文档问题、正常、复杂”这类保守答案走，宁可多花一次文本调用，也不误拒、不漏答。
- **失败有退路**：决策模型没配置、超时（访客路径 4 秒）或出错，就退回规则或原流程，页面和问答照常可用。
- **能复用就复用**：输入完全相同的判断按哈希缓存（如语言建议按信号组合、文档卡片按正文哈希）；访客私有的判断不跨访客复用。
- **只给需要的数据**：状态里不放 IP、账号、密钥；问题正文只在本轮判断里使用。
- **一律英文**：题目、选项、规则和状态全用英文，答案也是英文选项名。非英文内容先变成英文再交给决策模型，见下文“英文输入”。

## 各环节的用法

| 环节 | 题目 | 省下什么、改善什么 | 状态 |
|---|---|---|---|
| 访客语言建议 | 单选：最可能想读的语言 | 不靠猜浏览器语言；简中浏览器基本不看 IP | 已实现 |
| 每轮问答决策 | 意图、风险、是否独立、难度 | 离题和闲聊不检索不生成；独立问题不再改写；简单问题走快速档 | 已实现 |
| 文档路由 | 单选：哪篇文档最能回答（选项是文档卡片） | 先选对文档再检索，追问和宽泛问题也能找对地方 | 已实现 |
| 材料筛选 | 每段材料一道是非题：是否有回答需要的信息 | 路由没选中文档、改走片段检索时，只把有用的片段交给回答模型 | 已实现 |
| 文档卡片更新 | 是非题：旧卡片对新正文是否仍然准确 | 小改动不重写卡片，发布不必每次付费 | 已实现 |
| 回答核对 | 是非题：每个说法都能在材料里找到依据吗 | 核对不过的回答标“可能不准确”，不进缓存 | 后续 |
| 相关推荐 | 单选：已有问答和文档里哪些最相关 | 回答下面给“相关问题/相关文档”，文字取自现有内容，不生成 | 后续 |
| 文档缺口 | 路由选中“都不相关”且没有材料 | 后台汇总“访客问了但文档没写”的话题 | 后续 |
| 语义缓存 | 单选：相似旧问题里哪个能直接复用答案（含“都不是”） | 换个问法也能命中缓存；引用都没变的过期条目也能复用 | 后续 |
| 会话复查 | 单选：这段会话属于哪类滥用 | 只对可疑会话复查，处置附类别和概率 | 后续 |
| 翻译重译 | 每个改动块一道是非题：意思变了吗 | 改错字、标点不触发重译，“发布时自动翻译”才划算 | 后续 |
| 图片描述 | 是非题：这张图有信息量吗 | 装饰图不调视觉模型 | 后续 |
| 站内搜索直达 | 单选：哪篇文档最匹配搜索词 | 搜索框直接给最佳文档，不必等向量检索 | 后续 |

## 文档索引（index.md）

### 卡片

每篇已发布文档一张卡片，由知识索引在建索引时维护。卡片一律用英文写，不管正文是什么语言：

- **标题**：文档标题的英文。
- **摘要**：一两句话说清这篇讲什么（不超过 60 个英文词）。
- **主题**：最多 8 个关键词，产品名、配置项照原文写。
- **能回答的问题**：最多 3 个访客可能会问的问题。

改成英文之前写的卡片（没有英文标题）视为没有卡片，下次建索引时重写。

卡片按正文哈希保存，正文没变就不动。撤回或删除的文档不在发布树里，视图自然不含它；重新发布时旧卡片还能拿来做门控比较。

### 运行逻辑

1. 文档发布后照常建索引；分块和背景短句完成后进入卡片阶段。
2. 没有旧卡片：用文本模型（任务 `knowledge.summary`，快速档）读整篇正文写卡片。
3. 有旧卡片但正文变了：基准语言是英文时，先问决策模型（任务 `knowledge.decide`）“旧卡片对新正文是否仍然准确完整”，把握够（≥ 0.7）就沿用旧卡片、只更新正文哈希，否则重写；决策模型不可用时直接重写。基准语言不是英文时新正文不是英文，不做这一问，直接重写。
4. 卡片阶段失败不影响索引上线：旧卡片继续用，下一次发布再补。
5. 卡片只在发布时产生费用，符合“只有发布和用户批准的操作才触发付费任务”。

### 压缩逻辑

index.md 不是一份固定文件，而是按预算从卡片和文档树现算的视图，不调模型：

- **三级细节**：L2 = 英文标题 + 摘要 + 主题 + 问题；L1 = 英文标题 + 摘要；L0 = 英文标题 + 主题。
- **降级顺序**：先全部用 L2；超出预算时，按重要度从低到高把文档降到 L1，再降到 L0。重要度是该文档近期被问答引用的次数，越常被引用的越晚降级。
- **折叠子树**：降到 L0 还超预算，或选项超过 255 个，就把最大的子树折叠成一个分区选项（分区标题 + 子文档标题和主题的合并），从最深、文档最多的子树开始折叠。
- **两种视图**：全量视图（L1，按文档树缩进）给人看，后续也给 llms.txt 用（目前 llms.txt 仍用 SEO 描述）；路由视图按决策模型的预算生成，问答用约 12k token、最多 120 个选项。

### 路由

1. 访客问题能独立看懂时，路由题和每轮决策放进同一次调用；追问则在改写出独立问题、再译成英文后单独问一次（译不出来就只做全站检索）。
2. 选项是路由视图里的文档（或折叠的分区），另加一个“都不相关”。
3. 选中折叠分区时展开该分区，再问一次；最多展开两层。
4. 按概率取文档：最高的一篇作主要文档，累计概率到 0.9 为止的作补充（最多 3 篇）。
5. 选中的文章整篇交给回答模型：知识索引按文内顺序给出这些文章的全部分块，每块仍是一个可引用的单元。按决策模型给的先后装入预算（问答策略的“上下文最大词元”，默认 16000，且不超过回答模型可用窗口的三分之一），装不下的文章截断并标明，后面的文章不再给。
6. “都不相关”胜出、决策模型不可用或选中的文章读不到（例如新版本还没建好索引）时，改走片段检索：全站检索取候选片段，再做材料筛选，只留概率 ≥ 0.5 的（至少 1 段、最多 8 段）。

## 英文输入

决策模型只读英文。站点不管基准语言是什么，英文都始终启用并在发布后自动翻译（基准语言本身是英文时不需要）。各环节的英文来源：

| 输入 | 英文从哪来 |
|---|---|
| 访客问题 | 快速档文本模型译成英文（任务 `qa.english`，4 秒内）；页面语言是英文且只含 ASCII 字母时不译。译文记在本轮，之后几轮当作 `recentQuestions` 用 |
| 追问改写出的独立问题 | 前置改写给出基准语言的独立问题，再用 `qa.english` 译成英文 |
| 站点文档列表、路由选项 | 英文卡片（标题、摘要、主题、问题） |
| 材料片段 | 本地化服务里该文档的英文译文，取片段所在块的还原文本；还没有英文译文的片段不问，直接保留 |
| 语言建议的选项 | 语言的英文名 |

每轮决策的状态只有英文问题、此前最多 4 轮的英文提问和英文文档标题，不放回答原文和压缩摘要。翻译失败时这一轮的决策按“不可用”处理，走原流程。

## 问答一轮的新形态

```
访客提问
  → 风控限流（不调模型）
  → 非英文提问译成英文（快速档）
  → 决策模型：意图、风险、是否独立、难度、文档路由（同一次调用）
      ├ 闲聊 / 离题 → 固定回答，结束
      └ 风险 → 风控
  → 追问才调文本模型改写，译成英文后再单独路由一次
  → 精确缓存
  → 选中了文档：这些文章整篇（按预算截断）
    没选中：全站片段检索 → 决策模型筛材料（读英文译文）
  → 回答（记忆 + 摘要 + 历史 + 本轮文章 + 问题；简单问题用快速档，流式）
```

## 成本、延迟与隐私

- 每轮最多两到三次决策调用；按 Jev 的输入价格，一次 10k token 的路由约 0.0004 美元，远低于一次回答调用。非英文提问另有一到两次很短的快速档翻译。
- 访客路径上每次决策调用限时 4 秒，超时退回原流程。
- 决策模型的输入是英文问题、此前几轮的英文提问、文档卡片和材料片段的英文译文，会经过 OpenRouter 和 TypeSafe；不发送 IP、账号或密钥。Jev 的接口仍是 alpha，格式可能变化，固定版本号 `typesafe/jev-1.14`。
