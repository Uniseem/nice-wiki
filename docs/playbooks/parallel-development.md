# 多会话并行开发

允许不同会话同时开发不同模块，但每个会话使用独立 Git worktree 和分支。不得在同一工作目录切换分支、暂存、提交或修改另一个会话的文件。以 `codex/<模块>-<任务>` 命名分支；本次 main 文档重建完成后才启动业务实施。

## 所有权

一个会话只拥有一个 `modules/<slug>/`，包括本域未来源码、合同、文档、进度和交接记录。同一模块同一时间一个写入会话；确需进一步拆分时，由模块负责人先划定互斥文件清单。没有分配写入范围的会话只读。

集成会话独占根 AGENTS、STATUS、README、Makefile、scripts、contracts、全局 docs、部署拓扑和公共设计令牌。模块会话不得顺手更新根状态或另一模块接口；把公共变更请求写在自己模块的交接记录，集成会话统一处理。函数新增、辅助函数、职责或协议变化先修契约并遵守结构确认规则。

## 接口冻结与替代开发

领取任务时记录基线提交SHA、目标模块契约摘要、依赖模块版本、当前工作分支和独占文件。输入输出以该基线的 OpenAPI/types/events 为准。调用方只生成或实现自身版本化客户端，不导入对方内部代码，不增加影子 API，不读取对方私有数据。

依赖模块未实现时可以完成自己的纯规则、持久化与协议适配设计/实现；不能用返回空值的占位接口声称联调成功，也不能自行创建新测试或模拟样例。验收状态保持“等待依赖”，记录具体 operationId 与所需版本。

公共接口需要变化：模块会话列受影响操作/字段、原因、兼容方式和调用方→集成会话一次修改公共来源及所有消费者→检查通过并提交→通知相关会话把新的基线提交合入各自 worktree。禁止多个会话各自修改同一公共类型。

## 每次只做一项

按本域 docs/files、functions 和 progress.json 选择一个未来文件或一组紧密关联函数。先确认依赖及验收条件，再实现登记函数，随后运行当项已有检查、更新模块交接并提交。不得一次把全部 planned 标成实现完成，不得以行数或空函数通过进度验收。

推荐顺序：类型/生成入口→启动与配置→纯规则→私有持久化/CAS/恢复→用例和远程客户端→HTTP/SSE→UI→已授权的业务/集成验收。某函数依赖尚未实现时先实现依赖，仍无法进行则记录 blocked 原因和可继续的独立任务，不能猜测协议。

## 合并

1. 模块会话交付自己的提交SHA、精确修改文件、函数状态、验证证据、待依赖事项与契约变化列表。
2. 集成会话核对所有权，禁止带入另一模块或根文件的顺手改动；确认 OpenAPI/schema/事件和调用方版本一致。
3. 在集成分支合入一个模块，通过自部署 GitLab CI 的三个并行分片运行全部 `make build` 与完整 `make check`，并逐个审查新增逻辑：是否照合同、跨域响应形状与调用协议是否一致、恢复与崩溃路径能否走通、期限与上限是否符合合同；编译不过或逻辑有误不合入，只有通过才合下一项，不并发操作同一 Git index。
4. 文件冲突按实际契约修复，不能无脑采用某一侧；即使没有文本冲突，也检查事件、权限、费用作用域和状态迁移是否兼容。
5. 更新根汇总和模块进度。实现、检查、业务验收、部署分开记录，push 仍需要用户当次明确授权。

独立 worktree 解决工作文件和 Git 操作冲突；单一公共契约负责人及合并检查控制接口冲突。它们不能保证不存在设计或运行时问题。
