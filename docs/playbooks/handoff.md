# 跨会话与跨天交接

仓库是进度权威，聊天只用于补充解释。新会话不能因为看到某个文件存在，就推定它已实现、已检查或已验收。

## 新会话读取顺序

1. 根 AGENTS.md → STATUS.md → docs/plan.md → docs/README.md。
2. 目标模块 AGENTS.md → README.md → STATUS.md → progress.json → docs/handoff.md。
3. 按交接中“下一步”读目标函数、类型、API、流程、文件和验收条款；核对公共契约与依赖版本。
4. 用 `git status`、当前分支、HEAD 和交接中的提交SHA核对实际状态。脏工作区先区分谁的未提交改动，不覆盖、不删除，也不当成已经通过。
5. 声明自己拥有的模块/文件范围与本次一项任务，按并行开发手册使用独立 worktree。发现记录与代码不同则先纠正状态，不能靠旧聊天猜测。

根 STATUS 只汇总已合并 main 的状态。各模块 STATUS 是人类简表；progress.json 是逐文件、逐函数的机器台账；docs/handoff.md 解释最近完成、失败、决策和下一步。模块会话只写自己的三份记录，集成会话更新根汇总。

## 台账状态

`planned`：有设计，尚未实现；`in_progress`：本次工作中，必须标会话任务与未提交文件；`implemented`：登记行为已实现并有提交，尚未完成所需检查；`verified`：对应已有检查通过且有可核对证据；`accepted`：行为验收也通过；`blocked`：注明具体条件、所需操作与可继续工作。部署状态另记，不能把 accepted 等同已上线。

每条文件/函数记录有 ID/路径、状态、实现提交、验证说明和阻塞说明。格式/编译通过不能代替行为验收；未跑、依赖未就绪、失败或真实验收未授权均如实记录。没有实现的设计初始全部 planned。

## 结束前必须写

- 基线与交付提交SHA、分支、模块/独占文件范围；未提交文件清单和原因。
- 本次实际完成的文件/函数/需求ID，以及“仅设计”“已实现”“已验证”的区别。
- 检查命令、执行环境、退出结果和范围；只保存脱敏结论，不保存私有地址/原始业务数据/密钥。
- 遗留问题、依赖 operationId/版本、明确决策；新增测试/真实接口是否已有授权。
- 下一步只列一项可直接开始的任务：目标文件与函数、先读文档、依赖、完成条件；避免“继续开发”这种模糊指令。

并把 STATUS/progress/handoff 与本次实现一起提交。中断时允许未提交，但必须记录；新会话只能在确认这些改动的所有权后继续。尚未提交且交接也未保存的内容不能保证被另一个 worktree看到，不能假定 AI 有跨会话记忆。

## 可直接给新会话的指令

> 继续 nice-wiki 的 `<模块>`，先按 AGENTS.md 和 docs/playbooks/handoff.md 读取根与模块交接，核对 HEAD/工作区。仅拥有 modules/<模块>/，公共文件交由集成会话。先完成模块 docs/handoff.md 的“下一步”，逐项按精确函数契约实施并更新台账；不要猜接口，不把未验证工作标成完成，不增加未授权测试，不 push。

用户补充的新指令优先于旧交接；若改变需求，同步契约和记录，不能静默让文档失效。
