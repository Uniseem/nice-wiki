# 全局需求与边界

## 产品目标

提供可以编辑、预览、发布文档的站点；基础文档功能独立于可选 AI。AI 功能包含多渠道接入、长期记忆、带来源的流式问答、索引与缓存、翻译和术语。管理员能查看任务、风险、统计、费用，完成备份恢复与数据仓库同步。

这些功能按old产品设计保持全部功能与细节，只重新分配服务归属，不继承旧代码的文件/函数结构与实现耦合。当前没有上线新系统，也不复用旧数据作为新系统的运行数据。旧线上实例不在本次变更范围内。

## 强不变量

正文文件是权威，业务记录、会话、额度、任务和收费派生结果不是可随意重建的索引。服务不读写其他服务的数据库或可写目录。公开读取查权威发布状态；权限撤销不能仅靠慢事件。禁止模型密钥、账号、密码、提问正文与原始 IP进入日志或统计；允许问答正文作为 qa 私有、受控、按保留期限管理的业务数据。

草稿保存绝不调用模型。发布派生任务必须符合启用策略；全量重建、启用语言翻译和恢复等操作需批准计划。真实费用缺失不虚填零；取消不等于没有费用。未接入外部条件的功能报告缺能力，不用空实现冒充成功。

## 不扩展的产品范围

本轮不加入传统公开搜索、导入工具、实时多人协作、公开草稿分享、独立内容质量审查或新增模型护栏。编辑锁处理多人的冲突，不承诺共同实时编辑。风控模块是访问行为风控；“审查”不是代码审查模块。
