# AI 上下文与查询缓存

用户允许参考old的这些思路，并随后要求功能与细节保持old。需求来源为 [AI问答](product-baseline/design/ai-qa.md)、[记忆](product-baseline/design/memory.md)、[模型](product-baseline/design/ai-models.md)、[翻译](product-baseline/design/i18n.md)，后续D44/D46-D50/D53/D55优先。只继承思路与业务规则，不复制外部或旧代码。

## 五层上下文及所有权

| 层 | 内容 | 所属服务 | 版本和边界 |
|---|---|---|---|
| 任务指令 | 分类/核查/回答/翻译等任务自己的指令与输出格式 | 使用该任务的业务域 | taskId与指令版本；不是MG自行改写业务提示 |
| 长期记忆 | 项目概述、品牌语气、问答口径、通用/目标语言翻译规则 | memory | 按任务和语言ResolveContext，带说明与版本hash；1536B单条、5120B任务默认预算 |
| 对话 | 增量摘要、最近原样消息、新问题 | qa | 服务端保存，浏览器只持会话；清空两端同步，摘要CAS和对话版本绑定 |
| 当前页/材料 | 服务端验证的当前文档提示、召回块、小节、媒体描述与引用 | content/knowledge | 当前页只是优先参考，不能绕过发布可见性；只读发布修订 |
| 翻译邻域 | 整篇源文、当前批标签、前批/邻块译文、所在标题、匹配术语 | localization | 原块ID、源hash、人工generation、术语/记忆版本，陈旧任务拒写 |

共享任务清单见 [ai-tasks.json](../contracts/ai-tasks.json)；模型网关选择模型，记忆服务选择条目，业务域组装上下文。不存在三份独立任务枚举。

## 问答 agent 与阅读指南

当前问答由回答模型自主调用只读工具：浏览分区指南、混合搜索和读取当前发布正文；通用循环由 `libs/platform/modelagent` 执行。当前页预读为原生工具消息，可在窗口不足时移出后重读。具体工具和权限见 [问答架构](../modules/qa/docs/architecture.md)。

全站与分区 `AGENTS.md` 是 knowledge 生成的导航视图，使用当前发布目录和匹配内容哈希的已有摘要。指南在读取时维护版本，不在访客问答中额外调用模型，也不由访客问答修改。指南和正文都是资料，不能扩大工具权限或覆盖系统规则。

原生工具历史独立于访客原话保存，并在后续轮次前核对公开状态与发布版本；修改或撤回后停止重放旧正文。未经来源复核的旧式预读材料不继续注入，原问答记录保留。普通会话摘要用于接续语境，具体事实仍需正文证据。

任务覆盖模型按目录中固定默认档位的`tierCapabilities`校验：快速/精确要求chat，视觉要求vision，嵌入要求embedding，重排要求rerank。翻译沿用对话模型，不额外强制translation标签；不把结构化输出从建议提升为硬门槛。目录经`make gen`生成本域只读表，服务任务读取按owner收窄，管理读取与写入要求superadmin。

长期记忆放系统提示最前面，包含条目说明，再放任务指令；不能把材料当新的系统指令。记忆可能被公开问答复述，不保存秘密、内部流程或客户资料。只读条目助手不写；助手逐条提出新增/更新/删除/不变，人工批准才应用。项目概述被人工改过后不自动覆盖；翻译规则变化只提示重译估价，不自动花钱。

## 对话压缩

像编码代理（ADE）一样，默认不按条数截断，上下文快满才压缩。每轮回答前读出会话摘要和摘要之后的全部消息，按回答任务路线上各备用模型中最小的输入窗口计算预算：窗口 ×（1 − 预留比例，默认10%）− 回答输出额度。估算与模型网关核对窗口用同一口径（`platform.EstimateInputTokens`，偏保守，中文约为真实 token 的两倍）。

超过预算时用 `qa.compact`（快速档）把摘要之后、保留窗口之前的消息并入增量摘要：保留窗口取 min(retainedRecentTokens 默认15000, 可用历史预算 − 摘要空间)，并从一条访客问题开始；已有摘要时在其基础上更新。摘要按访客目标、已确认结论、访客偏好、未解决问题分节，按会话历史代数 CAS 提交，覆盖范围不能跳过或重复，会话清空后旧压缩结果拒写。后台关闭压缩时改为丢掉最早的消息。

提示词按供应方前缀缓存排列：系统提示与任务记忆 → 摘要 → 历史 → 本轮材料与问题。同一会话逐轮只在末尾追加，压缩之间历史前缀保持不变。前置改写只看摘要和最近6条消息。

## 缓存顺序

第一问：人机/程序风控→规范化精确查找→有效性门禁→命中直接返回；未命中再前置。追问：风控→前置结合摘要/最近消息/当前页补全为基准语言完整问题→精确→语义→检索。前置认为仍依赖未明上下文的问题不查也不写缓存。

精确规范化保留意义，用NFKC、空白/大小写及等价标点规范，不能把否定符或型号差异删掉。语义默认AI判定是否可直接复用，最多3候选；相似度阈值是可选方式，需要业务校准，不把“开启”和“关闭”当同义，不用rerank相关性冒充同义。查询embedding在同一根操作中只生成一次，缓存未命中传给检索复用。

## 缓存身份与失效

- canonicalQuestion使用基准语言，不按语言分库；回答按语言保存，缺目标语言时快速档自动翻译并保存，不能新增人工批准步骤。
- 命名空间含dataEpoch、规范化版本、EmbeddingSpace、问答记忆版本；EmbeddingSpace绑定供应方/模型版本/维度/预处理，同名不同空间禁止比较。
- 引用记录块ID和内容hash；块变化、撤回/删除令引用失效。无引用的“没有提到”回答在任意新发布后失效。事件迟到不能绕过输出前权威检查。
- 普通回答按可配置TTL过期；更换回答模型默认不清缓存，可手动清空。反馈“没帮助”的回答不能进入/继续命中普通缓存。
- 精选不过期、优先命中，沿old豁免记忆版本变化；不豁免撤回、删除和引用有效性。
- 关闭缓存仍保存问答记录；记录不含原始IP，按保留天数清理。报表分精确/语义命中、反馈与阈值建议。

## 付费边界与备用

缓存命中仍受风控。模型调用与缓存翻译继承可信rootOperationId/costClass；问答产生的嵌入/重排/核查/压缩也算问答，后台文档翻译和建索引单列。整站每日问答上限为0表示不限，小时会话/网络层费用限额可整体关闭；缺价格保留原警告和配置能力，账本标unknown，不能伪填0或谎称额度能准确覆盖未知费用。

五档有序备用、能力检查、结构化输出失败重试一次再换备用均保留。每attempt独立记录和预留，未知已发生费用先保守保留；取消不开始新的备用调用，已向用户输出后不拼接另一个模型回答。费用和取消分布式化，不削掉原自动备用功能。

## 与旧思路的差异范围

保留上下文、查询/cache流程和所有确认默认；只将共享内存状态改为域私有状态/API，将模型身份改为完整空间，将旧同步写回改为带修订CAS，将管理动作改为跨域事件/控制协议。旧草案“保存时调模型”及“换embedding自动全部重算”受后续发布/估价确认规则覆盖，不继承。没有复制opencode或其他GPL代码。
