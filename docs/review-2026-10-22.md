# 全站代码审查与修复清单

范围：当前 `main` 的十五个服务、`libs/platform`、后台与公开页前端，以及部署和恢复脚本。

**状态（2026-10-22）：20 项已全部修复**，并在独立本地实例上逐项验证；R05、R20 只做了本机 shell/SQLite 演练，仍需在 Docker 隔离卷上演练。以下保留原始问题描述与验收标准，供回归时对照。

原有 **20 项问题：5 项 P1、15 项 P2**。P1 涉及正文保留、全站可用性和恢复安全，应先处理；P2 是正常使用中的功能、权限和生命周期缺陷。

本清单记录触发条件、影响、实现位置和修复验收，不改变现有合同的技术约束。修复接口时仍须先改 OpenAPI 并生成代码；新增测试文件按根 [AGENTS.md](../AGENTS.md) 处理。浏览器交互、剪贴板以及破坏性恢复分支仍需在修复时完成对应行为验收。

## P1：可用性与数据保留

### R01：发布前验证完整祖先路径

位置：[publication_repository.go](../modules/content/internal/publication_repository.go) 的 `CommitPublication`、[path_service.go](../modules/content/internal/path_service.go) 的 `validatePathSnapshot`、[public_route_reader.go](../modules/content/internal/public_route_reader.go) 的 `readPublicRouteSnapshot`。

**触发与影响**：创建一个尚无 slug 的草稿父文档，再发布其子文档。发布成功，但子文档无法形成完整规范路径；首页、其他正常文章、导航和 sitemap 都依赖公开树，因此一起返回 `422 / INTEGRITY_ERROR`。撤回该子文档才能恢复这些读取。

**原因**：发布仅校验当前 slug、同父路径冲突和父节点是否活动，没有校验完整祖先路径。公开树遇到缺路径的已发布节点则返回整体错误。

**修复要求**：在发布提交前验证完整路径所需条件，相关移动操作遵守同一约束；无法形成有效公开路径时拒绝提交，并给出可操作的提示。

**验收**：覆盖无 slug 的草稿父节点、具有 slug 的草稿父节点和已发布父节点；失败的子文档发布不得影响已有文章、首页、导航和 sitemap。

### R02：保留行内结构变化后的人工译文与保护状态

位置：[translation/execute.go](../modules/localization/internal/translation/execute.go) 的 `runTranslation`、[translation/read.go](../modules/localization/internal/translation/read.go) 的 `ReadTranslation` 和 `LatestManifest`。

**触发与影响**：人工校对并保护一个段落后，仅将原文部分文字加粗，使一个文本槽位变成两个槽位。新译文可以进入 `ready`，但权威对象不包含该人工单元；单元列表变成空目标文本、`origin=machine`、`protected=false`，公开页不再显示人工译文。人工内容仍在旧对象中，但退出当前交付，也失去了下一轮增量翻译的保护依据。

**原因**：旧人工文本不能匹配新槽位时，执行器直接跳过该单元。读取端虽然尝试寻找前代，但新对象已完成时，最新对象和最新完成对象都是它自己，没有加载真正的上一份人工译文。

**修复要求**：明确保存前代来源与保护状态。不能安全映射的人工单元保留为待复核，不得通过省略单元形成看似完整的 `ready` 结果；读取和增量执行采用同一保护规则。

**验收**：覆盖局部加粗、链接变化、文本槽位拆分、表格结构变化及连续多次发布；人工内容与保护状态保持可追溯，待复核状态可见，不被后续机翻静默替换。

### R03：正文往返转换必须无损

位置：[convert.ts](../modules/content/web/src/convert.ts) 的 `fromBody`、`toBody`、`inlines`、`block`、`tableCell`，以及 [editor/blocks.ts](../modules/content/web/src/editor/blocks.ts)、[editor/image.ts](../modules/content/web/src/editor/image.ts) 等节点属性声明。

**触发与影响**：打开包含合同允许字段的正文，只修改其他位置再保存，原有字段也可能被静默抹掉。现有转换存在以下确定变化：

| 原正文 | 往返转换后 |
|---|---|
| `internal` 站内链接 | 链接 mark 被删除 |
| 分栏比例 `[0.7, 0.3]` | 重置成 `[0.5, 0.5]` |
| 图片或画板图注 | 写成空数组 |
| 表格单元格背景色 | 写成 `null` |

**原因**：内部链接被转换成空 `href` 后过滤；其余字段在保存时被硬编码重置。部分属性在编辑器节点声明中也缺失。

**修复要求**：同时补齐节点属性和转换映射。合同允许但暂不能编辑的字段必须保留，不能以静默删除的方式绕过保存校验。

**验收**：合法正文在未修改对应内容时，往返转换保留链接目标、图注、布局和样式；仅改变一处文字不会改写其他节点的业务字段。

### R04：历史导航执行同一保存检查

位置：[router.ts](../libs/platform/web/ui/router.ts) 的 `popstate` 监听与 `confirmLeave`，以及 [DocumentEditor.tsx](../modules/content/web/src/DocumentEditor.tsx) 的卸载清理。

**触发与影响**：存在未保存正文时，用浏览器后退或前进离开编辑器；若最后一次保存遇到断网、权限变化或锁失效，正文可能丢失。

**原因**：`navigate()` 会检查能否离开，但 `popstate` 直接通知路由更新。编辑器先卸载，清理中的 `flush().then(releaseLock)` 又不检查 `false` 返回值。同一页面内的历史导航不会触发 `beforeunload`。

**修复要求**：历史导航同样先完成保存或明确放弃修改的决策，再卸载编辑器；失败时保留当前正文和可恢复入口。

**验收**：在保存成功、断网、锁失效和权限失效时分别执行后退、前进；不能在未取得放弃修改决定时丢掉正文。

### R05：验证并暂存备份后再替换数据卷

位置：[restore.sh](../deploy/restore.sh) 及 [gen_deploy.py](../scripts/gen_deploy.py) 中对应的恢复脚本模板。

**触发与影响**：时间戳错误、缺少某个服务归档或归档损坏时，恢复脚本先删除该卷数据，解压才报错。若在后面的服务失败，前面部分卷已被替换，形成混合状态。

**原因**：没有在停机前检查全部归档，逐卷执行顺序是清空活动目录后直接解压，缺少完整暂存和回退路径。

**修复要求**：先检查全部归档存在、完整并属于同一备份集合，再解压到隔离位置；确认可用后替换活动目录，并保留原数据用于失败回退。修正生成器模板后重新生成脚本。

**验收**：归档缺失、损坏、解压容量不足和中途失败均不得先删除活动数据；替换失败时能够恢复原集合。演练仅使用隔离卷。

## P2：会话、任务与交付

### R06：跨标签页同步会话刷新结果

位置：[api.ts](../libs/platform/web/ui/api.ts) 的 `storeSession`、`refresh`、`request`，[App.tsx](../modules/portal/web/src/App.tsx) 的启动逻辑，以及 [session_service.go](../modules/identity/internal/session_service.go) 的 `IssueSessionTokens`。

**触发与影响**：新标签页因缺少授权缓存而刷新会话，共享 Cookie 随之更新，但原标签页仍使用自己的旧 CSRF。原标签页的保存和心跳返回 `403：CSRF凭据不匹配`；客户端只对 `401` 刷新，不能自行恢复。

**修复要求**：同步跨标签页的刷新结果并协调并发刷新，或提供无需轮换会话的当前会话状态读取接口。不要无差别重试所有权限错误。

**验收**：一个标签页刷新后，其他标签页可以继续保存和续锁；并发打开标签页不能因重复刷新而撤销有效会话。

### R07：续租原问答准入

位置：[turn/execute.go](../modules/qa/internal/turn/execute.go) 的 `renewLease`、[permit_store.go](../modules/traffic-guard/internal/permit_store.go) 的 `AcquireConcurrency` 和 `RenewPermit`。

**触发与影响**：前置处理、检索或压缩累计超过 30 秒，后续模型调用仍使用过期许可，以 `UNAUTHENTICATED` 失败。已开始的单次模型调用是否继续取决于其自身上下文，不能将问题理解为所有回答在第 30 秒统一断流。

**原因**：轮次执行允许 5 分钟，但周期续租只更新 QA 自己的执行租约，没有调用风控续租或更新签名许可。

**修复要求**：在原根操作和风控允许的最长窗口内续租并更新许可；续租失败后停止新模型步骤，不得换新根或延长消费授权。

**验收**：前置步骤超过 30 秒后，原获准轮次仍能继续；超出最长窗口、被封禁或被取消后不能继续消费。

### R08：取消控制请求使用新的短截止时间

位置：[turn/cancel.go](../modules/qa/internal/turn/cancel.go) 的 `cancelTurnDependencies`。

**触发与影响**：在最初 HTTP 请求的截止时间过去后取消，QA 已提交 `cancelled`，后续控制请求却沿用旧 `record.Operation`，返回 `504 / DEADLINE_EXCEEDED`，没有完整执行准入释放。

**修复要求**：为取消下游及释放准入建立新的短控制截止时间，保留原调用 ID、根操作、站点和数据代次；重放继续完成尚未确认的收尾。

**验收**：提问超过 30 秒后取消仍正常返回，轮次状态与控制操作结果一致，原准入完成释放。

### R09：登记并主动取消正在进行的模型调用

位置：[runtime/model_client.go](../modules/qa/internal/runtime/model_client.go) 的 `InvokeModel`、[turn/cancel.go](../modules/qa/internal/turn/cancel.go) 的 `InvocationIDs` 遍历，以及 [turn/start.go](../modules/qa/internal/turn/start.go) 的后台执行入口。

**触发与影响**：首个 token 之前、前置改写或压缩阶段取消时，模型调用可能继续运行到完成或超时。已有回答流可能通过下一次 delta 的状态检查间接停止，但没有及时停止的统一机制。

**原因**：执行链未将已接受的模型调用 ID 写入轮次，取消遍历为空；后台执行上下文也没有由取消接口直接终止。

**修复要求**：复用平台机制管理轮次上下文，并在模型调用被接受时登记 ID；取消应主动中断在途调用并阻止后续步骤，不依赖供应方继续输出 delta。

**验收**：覆盖首个 token 之前、前置处理、压缩和流式输出中的取消；只有原调用被取消，不产生新的模型任务。

### R10：业务幂等性不依赖每次新生成的准入

位置：[visitor_qa.go](../modules/portal/internal/visitor_qa.go) 的 `prepareVisitorQA`、[runtime/bootstrap.go](../modules/qa/internal/runtime/bootstrap.go) 的 `ReplayReceipt`，以及 [conversation/create.go](../modules/qa/internal/conversation/create.go)、[turn/start.go](../modules/qa/internal/turn/start.go)。

**触发与影响**：完全相同的创建会话正文和幂等键重试，首次返回 `201`，重试却返回 `409：同幂等键已用于其他输入`；随后新请求还可能被遗留准入挡为 `429`。

**原因**：入口每次生成新逻辑根和新准入并注入正文，QA 对包含这些临时字段的完整输入计算幂等摘要；冲突路径没有释放新领但未使用的准入。

**修复要求**：协调逻辑根、原业务回执和准入重放，在新领准入前返回既有结果；不能把每次生成的短期令牌直接作为业务输入身份。补全未使用准入的拒绝释放路径。

**验收**：创建会话和提问的同键同正文重放取得同一业务结果，同键异正文仍拒绝；重试不新增费用或遗留并发占位。

### R11：读取真实站点基准语言

位置：[qa/app/wire.go](../modules/qa/internal/app/wire.go) 的 `BuildApplication`、[answer/retrieve.go](../modules/qa/internal/answer/retrieve.go) 和 [knowledge/search/service.go](../modules/knowledge/internal/search/service.go)。

**触发与影响**：英文等非简中站点已建好正确语言的索引，问答调试或片段检索仍返回 `INTEGRITY_ERROR：查询不是当前基准语言和空间`。文档路由命中后的整篇读取可能成功，因此呈现为部分问题正常、部分失败。

**原因**：QA 的 `BaseLanguage` 固定为 `zh-Hans`，知识服务使用实际配置；改写和缓存作用域也受到硬编码影响。

**修复要求**：通过站点配置接口读取真实基准语言；未初始化时保持准确的依赖状态，不能默认成另一种语言。

**验收**：简中、英文和其他基准语言站点的调试、整篇路由、片段检索与缓存均使用正确语言范围。

### R12：入口及时刷新完整 SSE 事件

位置：[proxy_stream.go](../modules/portal/internal/proxy_stream.go) 的 `StreamResponse`。

**触发与影响**：上游已经提交并刷新进度事件，入口仍可能将其与后续答案一起延迟交付，短响应看起来一次性出现。

**原因**：入口使用普通 `io.Copy`，没有刷新 Go 响应缓冲区；`X-Accel-Buffering: no` 不能替代本进程的刷新。

**修复要求**：对 SSE 使用能及时刷新的转发方式，保留取消传播和背压；普通文件响应继续遵循其交付规则。

**验收**：暂停模型输出时，已产生的进度仍及时到达；分批产生的 delta 分批可见。计时应以完整事件帧为准，不能只观察响应头或 `event:` 行。

### R13：最终完整答案与前端显示对齐

位置：[modelclient/invoke.go](../libs/platform/modelclient/invoke.go) 的 `finishKnownGatewaySnapshot`、[turn/execute.go](../modules/qa/internal/turn/execute.go) 和 [island/client.ts](../modules/qa/web/src/island/client.ts)。

**触发与影响**：模型极快完成，或流中断后读到完整快照时，后台可能保存完整答案，浏览器却显示空答案或缺少尾部。

**原因**：公共客户端看到完整 `Output` 就返回完成，未必交付全部 delta；QA 前端只按 delta 累加，`completed` 事件没有最终答案内容。

**修复要求**：在 QA 层用权威完整答案对齐最终显示，或补读真实持久事件到完整水位；避免重复拼接已收到的文本，不伪造网关历史事件。涉及事件载荷变化时先更新合同。

**验收**：瞬时完成、正常流式完成和断流后完整快照三种路径中，前端最终文本与后台权威答案完全一致。

### R14：释放编辑锁后的失败必须恢复可保存状态

位置：[DocumentEditor.tsx](../modules/content/web/src/DocumentEditor.tsx) 的 `remove`、`onRollback`、`releaseLock` 和 `flush`。

**触发与影响**：删除或回滚先释放编辑锁，业务请求随后失败，界面却仍可编辑。用户继续输入时没有实际保存；离开检查也可能放行。

**原因**：失败后没有重取锁或切换只读；`flush()` 将没有 lease 与无需保存合并为 `true`。删除还忽略了保存返回的 `false`。

**修复要求**：失败后恢复编辑会话，或明确进入保留正文的只读状态；有未保存正文却无有效锁时不能报告成功，保存失败不得继续依赖保存成功的操作。

**验收**：删除或回滚遇到版本冲突、依赖故障后，原正文仍可恢复；再次编辑和离开不会误认为已经保存。

### R15：公开渲染接入站内链接解析

位置：[http_page.go](../modules/public-site/internal/http_page.go) 的 `renderPage`，对照 [preview_renderer.go](../modules/public-site/internal/preview_renderer.go) 的 `collectInternalLinks` 和 `RewriteInternalLinks` 接线。

**触发与影响**：合法内部链接指向有效公开文章，公开 HTML 仍显示“目标暂不可用”的 span，Markdown 也只剩文字。

**原因**：预览已有链接解析，但公开 HTML 和 Markdown 没有给渲染器传入 `Links` 映射。

**修复要求**：复用已有解析链路，按当前语言和当前公开路径构造链接，并保持目标可见性校验。

**验收**：公开 HTML 和 Markdown 中的文档及块链接可用；目标移动、改名、撤回后的行为一致。

### R16：剪贴板保留自定义媒体块的资源引用

位置：[editor/image.ts](../modules/content/web/src/editor/image.ts)、[editor/video.ts](../modules/content/web/src/editor/video.ts)、[editor/blocks.ts](../modules/content/web/src/editor/blocks.ts) 和 [editor/drawing.ts](../modules/content/web/src/editor/drawing.ts)。

**触发与影响**：通过普通 HTML 剪贴板复制自定义媒体块，节点可以被识别，但资源引用无法恢复，保存时报缺少资源引用。

**原因**：`asset`、`source` 等关键属性不参与 HTML 输出，`parseHTML()` 只匹配标签，没有恢复完整引用的规则；字节 URL 本身也不包含完整版本引用。

**修复要求**：提供对应的剪贴板序列化与恢复机制，保留资源引用；复制出的节点生成新稳定 ID，不修改原节点身份。

**验收**：实际浏览器内同文档和跨文档复制图片、视频、附件及画板，资源仍可访问，草稿可保存，复制节点 ID 不与原节点重复。

### R17：退出失败不能报告为退出成功

位置：[App.tsx](../modules/portal/web/src/App.tsx) 的 `signOut`。

**触发与影响**：撤销会话请求因断网或 CSRF 不匹配失败，界面仍跳到登录页；Cookie 继续有效，刷新后可能重新进入后台。

**原因**：代码吞掉撤销错误，仅清 `sessionStorage` 和界面状态。HttpOnly Cookie 与服务端会话并未因此失效。

**修复要求**：以服务端确认结果完成退出；失败时明确呈现状态并允许重试，不能将页面切换当作会话撤销。

**验收**：覆盖正常退出、断网和 CSRF 失效；成功后旧会话不可用，失败不会误报成功。

### R18：未公开资源使用 no-store

位置：[asset_bytes.go](../modules/media/internal/asset_bytes.go) 的 `ServeAssetBytes`。

**触发与影响**：未发布图片的匿名请求已经被拒绝，但管理员按带 SHA 地址读取时收到 `private, max-age=31536000, immutable`。同一浏览器配置可能持续使用新鲜缓存，后续访问不再经过当前权限检查。

**原因**：`private` 仅排除共享缓存，并未禁止浏览器自身缓存；这里没有遵守受保护预览的 `private, no-store` 约定。

**修复要求**：按资源实际公开状态选择缓存策略，未公开和预览资源不允许长期浏览器缓存，已公开不可变资源保持既定策略。

**验收**：未公开资源管理员读取为 no-store，匿名读取失败；正式公开资源仍能使用公开不可变缓存。

### R19：审计事实持久交付

位置：[audit/audit.go](../libs/platform/audit/audit.go) 的 `Record` 和 `send`。

**触发与影响**：analytics 短暂不可用时，其他服务的写操作成功，但对应审计记录永久缺失；发送方进程在协程完成前退出也有相同风险。

**原因**：成功请求之后仅启动一次后台 HTTP 发送，失败直接返回，没有持久待交付记录，也没有恢复后可补发的材料。

**修复要求**：复用平台 outbox/jobs 机制，使业务成功与待交付审计事实建立可靠关系；用稳定事件身份去重，不能仅增加即时重试。

**验收**：analytics 停机期间的成功写操作，在恢复后补齐且不重复；发送方重启不丢审计事实。

### R20：收紧备份进程的跨域文件权限

位置：[gen_deploy.py](../scripts/gen_deploy.py) 的 `data-protection` 用户与卷配置，产物为 [docker-compose.yml](../deploy/docker-compose.yml)。

**触发与影响**：备份进程以 root 运行，并读写挂载其他域的数据卷，拥有修改身份库、正文和模型网关数据的能力，不满足服务间不共享可写目录的架构底线。

**原因**：为了访问 SQLite WAL 共享内存文件，生成器省略了来源挂载的只读标记。应用以只读方式打开数据库不能替代文件系统权限隔离。

**修复要求**：验证可行的只读 WAL 读取方式，或由数据拥有服务导出快照，让保护服务读取导出物；写入限定在自身目录。不能未经验证直接加只读标记后宣称备份仍可用。

**验收**：从保护容器修改其他域数据被文件系统拒绝，备份仍能读取完整来源；通过隔离环境确认，不以真实服务卷试错。
