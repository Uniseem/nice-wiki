# nice-wiki 全面代码审查

日期：2026-10-22。范围：当前 `main` 工作区的十五个服务、`libs/platform`、后台与公开页前端、部署与恢复脚本。按入口授权、正文保存与发布、资源交付、模型任务、数据保留和恢复链路审查，未改业务代码。

## 结论

项目已经具备可运行的主链路，但现在还不宜承载需要保密的草稿或把在线备份作为唯一恢复手段。本次发现 **11 项问题：5 项 P1、6 项 P2**。其中草稿资源公开、删除后的撤销/回滚失败、图片变体不可访问已在独立空白环境通过真实接口复现；其余由代码调用链确认，未进行对应的故障注入或真实模型调用。

- **P1**：应在对外使用或依赖相关功能前修复，涉及保密性、内容丢失或恢复可靠性。
- **P2**：正常使用中的功能或生命周期缺陷，应进入近期修复。
- 本次未发现可以确认为 P0 的问题；这不代表所有安全场景均已覆盖。

## P1 问题

### R01：区分资源保留引用和公开访问授权

位置：[media/asset_bytes.go](../modules/media/internal/asset_bytes.go)，第 48–60、94–101 行；关联 [content/draft_service.go](../modules/content/internal/draft_service.go) 的 `confirmDraftPin`。

匿名读取只要求资源 ID、正确的 SHA，以及任意 `reference_sources.state='confirmed'` 记录。草稿保存也会确认资源引用，因此“为防删除而保留的草稿引用”被误当作“已经公开”。交付清单虽然给预览标记 `PrivateNoStore`，最终字节接口仍按自己的判断返回公共缓存。

**复现**：上传图片，插入从未发布的文档并保存草稿；不携带登录 Cookie 请求该图片地址。实际返回 **200**，并带 `Cache-Control: public, max-age=31536000, immutable`。

**影响**：知道草稿资源地址的人可以绕过管理员身份和预览授权获取资源，共享缓存还能继续保存这些字节。这里的前提是取得资源地址，不是声称资源 ID 或 SHA 可以被穷举。历史 pin 同样不能证明资源曾获公开授权。

**建议**：在资源域明确登记“曾经公开暴露”的资源版本/hash，只有这类资源可使用永久公开地址；其余读取校验当前管理员权限或有效预览凭证，并返回 `private, no-store`。草稿 pin 只用于防止清理，不参与公开授权。保持已发布 hash 的既有永久缓存语义。

**验收**：未发布图片匿名请求失败；受保护预览可以显示图片且不进入公共缓存；正式发布后的资源按既定公开策略访问。

### R02：让撤销和回滚与稳定 ID 生命周期相容

位置：[content/draft_commit_store.go](../modules/content/internal/draft_commit_store.go)，第 464–478 行；关联 [编辑器 ID 插件](../modules/content/web/src/editor/ids.ts) 和 [rollback_service.go](../modules/content/internal/rollback_service.go)，第 64–66 行。

保存时，正文中消失的 ID 被永久标记为 `retired`；后续保存只要再次带上该 ID 就返回 `INTEGRITY_ERROR`。编辑器的撤销会恢复原节点 ID，历史回滚也直接把旧正文交给 `SaveDraft`，两条正常产品路径都会触发拒绝。

**复现**：保存含 A、B 两段的草稿；删除 B 并保存；再次提交原 A、B 正文。返回 **422 / INTEGRITY_ERROR：正文复用了历史退役稳定ID**。对包含 B 的已发布历史执行回滚，也返回相同错误。

**影响**：自动保存完成后，用户的一次普通撤销即可使后续保存失败；历史版本含有后来删除的块时无法回滚。

**建议**：明确“同一文档恢复同一历史节点”与“复制出新节点”的区别。受控撤销/回滚应允许恢复有来源的 ID，或走显式的 ID 迁移和引用重映射；不能通过移除唯一性校验解决。前后端与合同应采用同一规则。

**验收**：段落、列表项、表格行/单元格的删除→保存→撤销→保存，以及历史回滚均成功；复制节点仍生成新 ID。

### R03：当前在线归档不能保证可恢复的一致状态

位置：[data-protection/simple_backup.go](../modules/data-protection/internal/transport/simple_backup.go)，第 138–168 行；关联 [restore-archive.sh](../deploy/restore-archive.sh)。

实际 HTTP 备份走 `simpleCreateBackup`，逐服务遍历数据目录；遇到数据库时才执行 `VACUUM INTO`，其他文件即时复制。`backupMu` 只串行化备份请求，未暂停正文保存、发布、任务或事件消费。单个 SQLite 快照的一致性不能覆盖正文文件和其他服务。

**触发场景**：备份已经遍历某篇文档所在目录，随后该文档保存了新修订；稍后才快照到的数据库指向新正文，但归档没有那份文件。即使文件与数据库恰好对应，各服务仍可能分别处于事件发布前、消费后的不同状态。

**影响**：备份被标记为 `ready`，恢复后却可能缺正文、隔离文档或留下不一致的引用/任务。当前恢复脚本只验证 tar 可读，不能发现这些业务关系问题。这项风险属于已经提供的在线备份功能，不是要求立即补齐所有 M4 屏障设计。

**建议**：短期先提供并明确使用停止写入后的离线完整备份；线上“完整备份”在具备一致性前应说明限制或拒绝成功标记。后续由各服务通过版本化接口导出自身快照，避免保护服务直接读取其他域的活动数据库和目录。

**验收**：备份期间持续保存/发布并产生任务，再从备份恢复；所有已提交正文、发布引用、资源与任务关系完整。不能只以数据库能打开或 tar 能解压作为恢复成功标准。

### R04：增量翻译没有保留源文变化后的人工保护

位置：[localization/translation/execute.go](../modules/localization/internal/translation/execute.go)，第 118–139 行；对照 [plan.go](../modules/localization/internal/translation/plan.go) 和 [edit.go](../modules/localization/internal/translation/edit.go)。

执行器只在 `prior.SourceHash == unit.SourceHash` 时复用上一份译文。源文一旦改变，新单元会直接加入模型批次，未检查上一单元的 `Protected` 或 `Origin == "human"`。仓库已有 `PlanIncrementalTranslation` 的保护与复核判断，但当前执行链没有使用它。

**触发场景**：人工校对某块译文并设为保护；保持块 ID，修改原文并重新发布。自动补译会对这个块重新机翻，新发布修订的译文由机器结果替代人工文本。

**影响**：保护标记在最需要发挥作用的增量更新场景失效；人工校对成果虽可能还留在旧译文中，却不再用于当前公开版本。

**建议**：执行器共用已有增量规划逻辑。受保护单元保留人工目标文本，源文变化时标记待复核；显式解除保护后才允许机翻。还应覆盖表格结构变化时父块与子单元的保护关系。

**验收**：保护块的原文修改和表格行拆分不触发该单元的机翻覆盖，后台能看到待复核状态。

### R05：离开编辑器前必须处理保存结果

位置：[DocumentEditor.tsx](../modules/content/web/src/DocumentEditor.tsx)，第 139–145 行；关联 [content/index.tsx](../modules/content/web/src/index.tsx)，第 26–29 行。

切换文档立即更新 `selected` 并卸载旧编辑器；清理函数才调用 `flush().then(releaseLock)`。`flush` 在失败时返回 `false` 而非拒绝 Promise，所以失败后仍释放编辑锁。旧正文只保存在已卸载组件的 ref 中，没有恢复入口。`beforeunload` 不能拦截这种应用内切换。

**触发场景**：输入后立即切换文档，此时网络中断、版本冲突或编辑锁失效；最后一次自动保存失败。

**影响**：界面已经离开原文档，重新打开只能读到服务器旧草稿，未保存输入丢失。

**建议**：让文档切换和离开页面共用离开检查，成功保存后再卸载和释放锁；失败时保留编辑器，提供重试或明确放弃操作。不要只在卸载回调里启动保存。

**验收**：模拟保存失败后切换文档，未保存文字仍可编辑、复制或重试；保存成功时正常切换。

## P2 问题

### R06：图片变体需要随原图建立引用与交付关系

位置：[media/attach_variants.go](../modules/media/internal/attach_variants.go)，第 67–75 行；关联 [asset_bytes.go](../modules/media/internal/asset_bytes.go)，第 48–53、147–152 行，以及 [public-site/media_client.go](../modules/public-site/internal/media_client.go)。

关联变体只更新原图的 `asset_json`，文档保存只 pin 正文里的原图引用。公开渲染会把变体生成 `srcset`，但变体字节接口要求它自己有 confirmed pin，因此被拒绝。

**复现**：上传 2000 像素宽的原图与 640 像素宽的变体，调用关联接口，插入文档并发布。公开页返回 200 且包含变体 `srcset`；无登录直接请求变体返回 **404**，发布前后结果相同。

**影响**：浏览器选中变体时图片加载失败；没有引用保护的变体还可能被列为未引用资源。后者是代码推导，本次未执行资源删除。

**建议**：资源域维护原图→变体的版本化依赖，原图的保留与公开授权应覆盖相应变体。交付清单只输出可读取且受保护的变体。

**验收**：匿名读取 `srcset` 中每个地址成功；原图仍在使用时，变体不能被清理。

### R07：重启后需终结或恢复失去执行者的问答轮次

位置：[qa/turn/start.go](../modules/qa/internal/turn/start.go)，第 47–59、104–110 行；关联 [qa/app/wire.go](../modules/qa/internal/app/wire.go)，第 134–148 行。

轮次写入数据库后直接通过 `context.Background()` 的 goroutine 执行。启动装配只运行 outbox 循环，没有恢复或终结遗留轮次的处理。下一次提问只判断非终态轮次数量，不判断它是否已经失去执行者或租约过期。

**触发场景**：问答处于 queued/retrieving/generating 时重启服务，继续使用原会话。

**影响**：会话持续返回“上一个问题还在回答”，原回答也没有新的终态。等待执行租约过期不会自动解决；用户只能另开会话或主动取消旧轮次。

**建议**：先补最小启动收尾，把明确失去执行者的轮次标为失败并释放准入；有已接受模型调用的只读核对原结果，不能用新键重新付费。后台执行纳入平台已有任务生命周期。

**验收**：在几个阶段重启服务，旧轮次最终可读到终态，同会话可以继续提问。

### R08：将问答记录保留策略接入实际创建和清理流程

位置：[qa/app/wire.go](../modules/qa/internal/app/wire.go)，第 134–148 行；[qa/conversation/create.go](../modules/qa/internal/conversation/create.go)，第 83 行；关联 [runtime/prune.go](../modules/qa/internal/runtime/prune.go)。

后台提供 `recordRetentionDays` 设置，但新会话到期时间固定为 30 天；`PruneExpiredRecords` 在业务代码中只有定义，没有调用入口。过期校验只是拒绝读取，不会清除数据库里的提问、回答、摘要及事件。

**影响**：配置的保留天数与实际行为不符，访客正文长期留存；问答事件和诊断数据持续增长。遗留的非终态轮次还会被现有清理查询排除，需要与 R07 一起收尾。

**建议**：创建会话使用当前策略，并用平台周期循环调度已有清理函数；明确策略修改对存量会话的处理，保证终态事件和诊断记录也按各自期限删除。

**验收**：缩短策略后，受策略约束的数据在期限后实际清除，不能只验证 API 不再展示。

### R09：标题翻译也必须检查取消状态

位置：[localization/translation/execute.go](../modules/localization/internal/translation/execute.go)，第 141–149 行；关联 [cancel.go](../modules/localization/internal/translation/cancel.go)。

正文批次经 `flush` 检查取消；标题则直接调用 `translateBatch`。如果用户在最后一批正文执行期间取消，正文调用返回后仍会新发起一次标题模型调用；正文全部复用时也绕过了批次前的取消检查。

**影响**：取消已成功返回之后，仍可能产生一笔新的模型请求及费用。这里不是指无法撤销已经发出的正文调用。

**建议**：所有模型派发共用取消检查，标题也走同一入口；写最终结果前复核任务状态，只有仍在运行的任务才允许提交。

**验收**：最后一批正文执行中取消，正文结束后不再出现标题调用；全部正文复用时取消同样有效。

### R10：过期会话错误码与前端恢复分支不匹配

位置：[qa/web/island/client.ts](../modules/qa/web/src/island/client.ts)，第 79–85 行；对照 [qa/runtime/bootstrap.go](../modules/qa/internal/runtime/bootstrap.go)，第 223–225 行。

服务端对已过期或删除会话返回 `GONE`，前端只有在 `NOT_FOUND` 时才清除缓存的会话 ID 并新建会话。

**影响**：用户保留标签页直到会话过期，再提问会不断复用同一个失效 ID；代码所承诺的自动新建不发生。

**建议**：对 `GONE` 执行同样的一次性新建流程，并正确结束旧消息状态；保留重试次数上限。

**验收**：使当前会话过期后提问，只新建一次会话并正常继续，其他授权错误不触发此分支。

### R11：访客会话缓存需要绑定语言

位置：[qa/web/island/client.ts](../modules/qa/web/src/island/client.ts)，第 62–69 行；关联 [qa/turn/start.go](../modules/qa/internal/turn/start.go)，第 82–87 行，以及 [QaChat.tsx](../modules/qa/web/src/island/QaChat.tsx) 的 `nw-qa-log`。

浏览器只保存一个 `nw-qa-conv`。`conversation(language)` 找到 ID 就直接返回，不比较语言；后端每轮使用数据库中已有的 `conversation.Language`。聊天记录也使用全局的会话存储键。

**触发场景**：在中文站点发起对话，同一标签页切到英文或其他语言后继续问答。

**影响**：页面语言已经改变，回答语言、前置改写和缓存查询仍按旧会话语言处理，聊天记录也混入旧语言上下文。

**建议**：按语言保存会话 ID 和对应消息，或切换语言时明确新建会话；不能只把新语言参数传给一个始终返回旧 ID 的函数。

**验收**：同一标签页切换中英文后提问，各会话使用对应语言，消息与会话 ID 保持一致。
