# 实施计划（2026-10-21 精简版）

旧版冻结计划（R1 工作包、函数台账计数、CI 证据链）已从流程中移除，需要时到 git 历史里查。现在的原则是：先让东西跑起来，再逐步补全。当前进度只看 [STATUS.md](../STATUS.md)。

完成尺度以 [全局需求](requirements.md)（G01–G24）、[需求保留矩阵](product-preservation.md)（B01–B19）和[界面装配](frontend.md)里的页面为准，函数数量不算进度。不删减已确认的产品功能（回收站、历史回滚、预览、编辑器、多语言、SEO、llms、媒体视频、问答岛、备份镜像等）；范围的增减由用户决定。

## M1 主链路可运行

服务：identity、site-config、jobs、content、portal、public-site。

在本地完成：初始化站点 → 超管登录 → 新建文档 → 编辑保存草稿 → 发布 → 公开页可见 → 撤回。

完成标准：上述几个服务能在本地同时启动，并用浏览器走通整条链路。

## M2 资源与后台补全

服务：media、analytics、traffic-guard。

- 上传和插入图片、视频。
- 历史、回滚、回收站。
- 后台各页面可用。
- 公开访问的风控和统计。

## M3 AI 能力

服务：model-gateway、knowledge、memory、localization、qa。

- 接入模型供应方和费用账本。
- 索引检索、问答岛、翻译、长期记忆。

真实模型调用需用户当次同意。

## M4 保护与恢复

服务：data-protection，以及各域的屏障、快照、恢复换目录、全域封口。

- 一致备份、恢复、data git 同步。

## M5 部署

内容：deploy 编排、各服务镜像、Caddy。

部署到服务器需用户当次同意。

每个里程碑内部按"能跑 → 补功能 → 补边界"的顺序推进，不追求一次写完合同里的所有分支。
