# 部署与运维要求

每服务独立构建产物、配置、数据目录、schema迁移、健康/能力/版本报告。数据根分active/control/restore三部分，进程必须由守护自动重启（ADR0003：恢复切换依靠退出码75后重启换目录）。服务地址通过部署配置注入；公开入口只到portal/public-site，其余API内网且有服务身份。首次部署保持初始化和账号注册受保护；没有AI也能建立文档站。

当前仅有设计与检查脚本，无业务二进制、Docker服务或生产运行数据。计划服务代码与容器文件在模块files契约登记后才能创建，不把设计阶段的make check冒充构建或上线。

8核4GB环境先单机多服务，内存密集构建/分析分批，后台索引翻译并发受渠道和费用限额约束。独立进程可迁多机；有状态服务的多副本须先确认事务存储/租约实现，不以共享本地文件作集群。

只从私有vps.txt读连接信息；该文件与环境/凭据/运行数据/Git元数据均不同步。使用隔离检查目录，不改变旧线上实例、域名、代理或数据库。本次未授权发布新实例，也未授权push。

备份和恢复必须遵循全站维护屏障与切换决策日志（ADR0003：暂存后由进程守护重启换目录，部署须配置自动重启）；失败保留最后可用备份与旧代，恢复不自动调用模型。远程data git凭据只属data-protection，代码Git同步仍遵循用户每次授权规则。
