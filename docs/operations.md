# 部署与运维要求

每服务独立构建产物、配置、数据目录、schema迁移、健康/能力/版本报告。进程由守护自动重启。服务地址通过部署配置注入；公开入口只到portal/public-site，其余API内网且有服务身份。首次部署保持初始化和账号注册受保护；没有AI也能建立文档站。

当前仅有设计与检查脚本，无业务二进制、Docker服务或生产运行数据。计划服务代码与容器文件在模块files契约登记后才能创建，不把设计阶段的make check冒充构建或上线。

8核4GB环境先单机多服务，内存密集构建/分析分批，后台索引翻译并发受渠道和费用限额约束。独立进程可迁多机；有状态服务的多副本须先确认事务存储/租约实现，不以共享本地文件作集群。

只从私有vps.txt读连接信息；该文件与环境/凭据/运行数据/Git元数据均不同步。使用隔离检查目录，不改变旧线上实例、域名、代理或数据库。本次未授权发布新实例，也未授权push。

备份和恢复：站点导出包与全平台备份见 [consistency](consistency.md) 的“备份恢复”；失败保留最后可用备份，恢复不自动调用模型，代码 Git 同步仍遵循用户每次授权规则。

部署编排见 [ADR0005](adr/0005-engineering-and-deployment.md) 与 [deploy](../deploy/README.md)：Docker Compose 运行 15 个服务与 Caddy，`restart: unless-stopped`；端口、内存上限（GOMEMLIMIT 合计约 2.6GiB）、数据卷与公钥表各有唯一来源。部署、升级、日志与密钥轮换都在 deploy/ 中完成，代码与部署变更仍需用户每次授权。
