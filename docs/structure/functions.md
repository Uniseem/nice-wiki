# 文件与函数登记要求

每个未来手写Go/TypeScript/Vue文件有固定用途和函数清单；纯类型/配置文件声明没有行为，生成文件声明来源而不手写。

函数合同分两级（[ADR0002](../adr/0002-event-delivery-and-contract-levels.md)）：

- 约束级（binding）：OpenAPI x-handler、events.json 消费 handler、outbox 转发与事件订阅循环、任务执行函数、进程启动/健康入口和界面挂载入口。名称、精确签名、输入输出、步骤、错误、副作用、授权、幂等、并发与依赖照合同实现；要改先修合同。
- 参考级（reference）：其余内部函数，是建议的拆分方式。实现时可以增删、合并、改名或换文件，不用登记，也不用回写合同；已有条目只作提示，碍事时可以删掉。参考函数步骤里写明的业务规则属于上层约束函数的行为，不能因为拆分调整而丢掉。

每条函数写唯一ID（模块slug.函数名）、精确签名、参数与约束、返回值、作用、实际分支步骤、可能错误、数据/网络/费用副作用、授权、幂等、并发锁/租约/CAS，以及调用的同域函数ID或跨域“模块:operationId”。存储、外部库、协议说明等非函数依赖写在resources。

人类 functions.md 与 files.md 由 `make docs` 生成。`make check` 校验依赖可解析、签名约定、事件链接通，以及文档与合同一致。函数契约能够降低猜测，但正确性仍需设计审阅和已授权的行为验收。

全局检查脚本自己的入口/工具职责见 [工具函数合同](tooling.md)。
