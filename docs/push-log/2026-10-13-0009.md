### P1：需优先修复

1. **R01：撤回或删除文档后，公开问答仍能检索其正文。** `server/internal/app/app.go:288` 从 `retrieval_units` 取材料时不关联当前文档的发布状态；`Withdraw` / `Trash` 只重建 documents/blocks，未删除检索单元、向量、FTS 数据，也未使回答缓存失效。已索引文档撤回后，页面关闭但问答仍可能披露原正文。检索必须校验当前发布状态，并在撤回、删除及排队任务执行时同步清理和失效。
2. **R02：关闭 AI 后，接口仍调用付费模型。** `server/internal/api/public_ask.go:24` 只检查 QA 指针；该服务在启动时无条件创建。管理员关闭 AI 只隐藏页面入口，持有有效问答 cookie 的访客仍可直接 POST ask。接口应在任何模型调用前检查当前开关和可用条件。
3. **R03：每日花费上限不能阻止继续消费。** `server/internal/ai/qa/service.go:67` 先调用回答模型，随后才在 71～75 行计费和拒绝；达到上限后，每次新请求仍执行付费调用。另外以 token 数除以一百万当作美元，未采用实际模型价格，嵌入和压缩费用也没有纳入。应在调用前检查/预留额度，并按实际调用费用结算，失败或超限仍记录已发生费用。
4. **R04：浏览器 PoW 无法建立问答会话。** `server/internal/api/public_session.go:14` 将带端口的 RemoteAddr 直接放入冒号分隔的 challenge；`server/internal/ai/guard/pow.go:27` 要求 Split 后恰好四段。IPv4 的 host:port 会形成五段，IPv6 更多；即使哈希计算正确也被拒绝。需使用无歧义编码并校验挑战所属访客。
5. **R05：自动翻译覆盖人工译文。** `server/internal/i18n/translate/pipeline.go:43` 将所有未复用块写为机器译文，未检查 SourceHuman。人工译文只要源文 hash 改变，或译文长度未达到复用门槛，下一次发布就会被覆盖；任务运行期间的人工编辑也会被整文件旧快照覆盖。应保留人工内容并标待复核，提交结果前核对源文代次与译文版本。
6. **R06：备份把独立 SQLite 快照与运行中 WAL 混装。** `server/internal/backup/export.go:81` 只排除 wiki.db，仍复制 wiki.db-wal / wiki.db-shm。归档里的主库来自 VACUUM INTO，而 WAL 属于原始库且可能继续变化；恢复时将它们放在一起，可能重放不属于该快照的页或无法打开。应只携带一致快照，排除 WAL/SHM、运行锁和临时文件。
7. **R07：恢复流程不支持提供的 Docker 数据卷部署。** `server/internal/setup/restore.go:46` 把整个数据根目录重命名为同级 .pre-restore；准备阶段也把暂存目录建在根目录的父目录。Compose 将数据卷直接挂载到 /data，非 root 用户不能在 / 创建暂存目录，挂载点本身也不能按此流程重命名。恢复工作目录和替换范围必须位于可写持久卷内部，同时保留失败回滚能力。

### P2：功能与一致性问题

8. **R08：后台保存模型不更新实际运行档位。** `server/internal/app/app.go:486` 仅在启动时把目录复制到 TierStore；`server/internal/api/admin_models.go:30` 保存仅更新 Catalog。首次配置 chat/embedding 后，可用性检查读取新目录而准许启用，实际问答和索引却继续使用空档位，直到重启才生效。应同步更新运行分配，并基于实际可调用档位计算就绪状态。
9. **R09：追问没有使用对话历史。** `server/internal/ai/qa/service.go:63` 直接检索当前原始问题，67 行调用 Answer 只传当前问题、材料和记忆。已保存的 Turns/Summary 从未送入问题改写或回答；例如先询问产品 A，再问“它怎么安装”，无法保留指代，且原始追问被用于全站共享缓存。应先用历史补全追问，再按完整问题检索和缓存。
10. **R10：缓存命中时浏览器显示空答案。** `server/internal/ai/qa/service.go:54` 命中只发送带 Text 的 done 事件；`web/src/site/chat/useChat.ts:10` 只用 text 事件追加答案，done 仅保存会话 ID。相同问题第二次提问会得到空助手消息。缓存和非缓存路径应共用答案事件序列，并记录返回的助手消息。
11. **R11：问答引用字段无法被前端读取。** `server/internal/ai/qa/events.go:10` 的 Citation 无 JSON 标签，输出 DocumentID/BlockID/Title/URL；`web/src/site/chat/MessageItem.vue:2` 使用 blockId/title/url。非空引用最终显示空标题，链接变成 undefined#b-undefined。需要在唯一契约与序列化边界统一字段名。
12. **R12：译文应用会破坏行内格式与代码。** `server/internal/i18n/translate/files.go:107` 把整块译文塞进第一个 text 节点，随后清空其他 text 节点，保留的 marks 只属于第一个节点。含加粗、链接、行内代码的段落因此丢失各段格式与代码，或整段意外继承第一个链接；容器块还递归改写子块。应逐段提取/回填并保留不可翻译节点，接通占位编码与校验。
13. **R13：译文完成或人工修改后，公开 HTML 仍返回旧缓存。** `server/internal/site/page.go:107` 的 key 未包含译文内容/版本和翻译字符串；流水线和人工保存也未清理 Site cache。翻译前第一次访问留下的原文页面，或修改前的译文，会一直命中旧 HTML/ETag，直到其他元数据变化、容量淘汰或重启。需要以渲染依赖的译文版本构成 key 或在写入时失效缓存。
14. **R14：统计混入爬虫，并把 AI 爬虫浏览计为两次。** `server/internal/stats/rollup.go:34` 读取时丢弃 bot 字段，92～94 行对 AI 记录同时增加 Views 和 AICrawls，63 行又把两者相加写进 views。一条非空路径的 AI beacon 因而计为两次普通浏览；AI 专用维度仅在空路径时生成，正常有路径的记录不会出现该维度，后台 AICrawls 仍为零。应分别汇总人类浏览与 AI 爬虫读取，普通爬虫按约定过滤，避免重复计数。
15. **R15：其他语言页面的问答始终按基准语言处理。** `server/internal/api/public_ask.go:33` 无条件使用 Base；AskInput 及前端请求没有携带访客语言，也未从页面/语言 cookie 中解析。访客在非基准语言页面提问，记忆选择、记录、缓存分区和引用链接仍使用基准语言，Answer 也没有目标语言指令。需在契约和客户端传递语言，按启用清单校验，再贯穿改写、材料、回答和缓存流程。
