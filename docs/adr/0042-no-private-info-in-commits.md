# D42. 提交中不得包含隐私信息（硬性规定）

- 状态：✅ 已定
- 日期：2026-10-12

仓库是公开的，提交出去的内容可能马上被缓存、被搜索引擎收录，事后删除也无法完全收回。所以这是硬性规定，写进 `AGENTS.md`。

## 禁止出现在提交里

范围包括提交信息、文件内容、提交的作者和提交者信息：

- 真实邮箱地址
- 真实姓名（GitHub 用户名除外）、电话、住址等个人信息
- 含用户名的本机路径（如 `/Users/<用户名>/...`、`C:\Users\<用户名>\...`）、本机用户名、主机名
- 真实 IP 地址。文档示例只能用文档专用的地址段：`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`、`2001:db8::/32`
- 密钥、令牌、密码、cookie
- 没有公开的账号信息，例如用户的其他 GitHub 账号
- 访客的数据：问答记录、日志片段、统计明细

## 署名必需的例外

- 作者邮箱：只能是 GitHub 提供的代用地址 `<id>+<用户名>@users.noreply.github.com`。
- AI 合著者：厂商公开的无回复地址，例如 `noreply@anthropic.com`（见 D41）。
- 文档里的示例域名用 `example.com` 这类保留域名。

## 执行方式

- **每次提交前**，AI 助手检查暂存的改动和提交信息。
- **提交前确认 git 配置的作者邮箱是 GitHub 代用地址**。如果不是，停下来告诉用户，不能自行修改 git 配置。
- **push 前**，对所有待推送的提交再扫描一次（写进 `docs/playbooks/push.md`）。
- **发现问题时**：
  - 还没提交：从改动里去掉；
  - 已提交但还没 push：停下来报告，用户同意后再修改提交；
  - 已经 push：立即告诉用户。是否改写历史、是否作废泄露的密钥，由用户决定。
- 第 0 阶段做一个自动检查脚本，接入 git 提交钩子和 `make check`，把上面的人工检查自动化。
