# D38. 测试规范：测试由用户决定

- 状态：✅ 已定
- 日期：2026-10-12

详见 [design/engineering.md](../design/engineering.md)。

- **测试由用户决定，AI 助手不能自行增加。** 写进 `AGENTS.md` 的硬性规定：
  - 可以自行运行已有的检查：格式化、lint、类型检查、已有的测试；
  - 以下操作必须先问用户：新增或修改测试（包括样例文档和快照）；在计划里增加测试阶段；运行端到端测试、真实接口测试、AI 评测；
  - 已有测试失败时，只能改业务代码或停下来报告，不能修改、删除、跳过这个测试。
- 完成的定义：代码和文档已更新，并且 `make check` 全部通过。测试不算在完成的定义里。
- 用户同意写测试之后，按以下写法：不设覆盖率指标；优先测修过的 bug、各种块类型、后台接口的权限。
- 前后端共用 `fixtures/` 里的样例文档：三个渲染器的输出做快照比对，同时检查 Tiptap 和 Go 两边的渲染是否一致。
- 普通测试不调用真实的外部服务，用假实现代替；真实调用的测试要设置 `LIVE=1` 才运行。
- 和时间有关的逻辑用 `testing/synctest` 测试。
- 权限测试遍历所有路由，没有声明权限的接口直接判为失败。
- AI 效果用 `evals/` 里的评测题集衡量，手动运行。
- `make check` 跑完所有检查，全部通过才算完成。
