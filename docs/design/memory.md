# 长期记忆（草案）

> 状态：讨论中。对应决策记录 D46。标 🟡 的是用户没有明确选择时采用的默认做法，可以推翻。

## 定位

一个**独立的功能模块**，和"模型接入"（ai-models.md）同级：

- **统一维护一套记忆**：项目背景、品牌语气、问答口径、翻译规则等。
- **各个功能按需取用**：问答、翻译、刷流判断、描述生成等，各自取用相关的几条，注入给模型的提示词。

```
模型接入：  渠道 → 模型 → 档位 ──┐
                                ├──▶ 任务（问答、翻译、刷流判断……）
长期记忆：  记忆条目 ────────────┘
```

两个模块服务的是同一份**任务清单**：模型接入决定"这个任务用哪个模型"，长期记忆决定"这个任务带上哪些背景和规则"。任务清单只在一个地方定义（`server/internal/aitask/`）。

记忆和**缓存**是两个独立的模块：
- 记忆是人维护的知识和规则；
- 缓存是已经给出过的回答的副本。

两者之间只有一处联动（见下文"记忆变化之后"）。

## 记忆条目

每个条目是一个 Markdown 文件，存放在 `data/memory/`，纳入 git，可以回滚。

```markdown
---
title: 翻译规则 · 日语
description: 日语的文风和敬语用法，只在翻译成日语时注入
lang: ja            # 可选：只在翻译成这种语言时生效；不写表示对所有语言生效
source: manual      # manual = 手动维护 | assistant = 由助手整理 | auto = 由定期任务自动维护
---

- 统一使用です/ます体
- 产品名保留英文，不要转写成片假名
```

### 内置条目

站点初始化时创建，内容由你或者助手来写：

| 条目 | 内容 | 来源 |
|---|---|---|
| 项目概述 | 这个站点是做什么的，涵盖哪些主题 | **自动维护**：原来生成"站点概述"的定期任务，改为更新这个条目。你手动修改之后就不再覆盖，除非重新打开自动更新 |
| 品牌与语气 | 受众是谁、用什么语气、怎么称呼访客 | 手动 |
| 问答口径 | 该说什么、不该说什么，例如账单问题引导到客服页、不评价竞品。原来的"回答风格"设置并入这里 | 手动 |
| 翻译规则 · 通用 | 对所有语言都适用的翻译规则 | 手动 |
| 翻译规则 · \<语言\> | 某种语言专属的文风规则，例如日语用敬体、德语用 Sie。带 `lang` 标记 | 按需创建 |

你可以自己增加更多条目。

### 大小上限

- **单个任务一次注入的记忆总量不超过 5KB**（按 UTF-8 计算，大约相当于 1700 个汉字）。
- 后台会显示每个任务当前的注入量。如果保存某个条目、或者修改某个任务取用的条目之后，有任务超过 5KB，就拒绝保存，并指出是哪个任务超了。
- 超出时由助手负责处理：合并重复的内容，精简措辞。

## 每个任务取用哪些条目

每个任务都有默认取用的条目，可以在记忆模块的界面里调整。

| 任务 | 默认取用的条目 |
|---|---|
| 前置判断：问题分类、刷流判断、改写 | 项目概述 |
| 检索核查、入库时补上下文 | 项目概述 |
| 生成回答 | 项目概述、品牌与语气、问答口径 |
| 缓存命中判断 | 项目概述 |
| 把缓存的回答翻译成访客的语言 | 品牌与语气、翻译规则 · 通用、翻译规则 · 目标语言 |
| 文档翻译、站点文字翻译 | 项目概述、品牌与语气、翻译规则 · 通用、翻译规则 · 目标语言 |
| 图片、画板、视频、附件的描述 | 项目概述 |
| 路径名、SEO 描述 | 项目概述、品牌与语气 |
| 语言切换建议 | 不取用 |

"翻译规则 · 目标语言"是自动挑选的：翻译成日语时，只带上标记为 `lang: ja` 的条目。

### 在提示词里的位置

记忆放在系统提示词的**最前面**，排在任务自己的指令之前。记忆很少变化，各家模型的提示缓存都能命中，重复注入几乎不额外花钱。

## 记忆助手

记忆模块的界面左边是条目列表，显示每个条目的大小、被哪些任务取用；右边是和助手的对话。你用自然语言说需求，助手负责整理进记忆。

- 使用**精确档**的模型。
- 助手可以做的操作：
  - 读取、新建、修改、合并、删除条目；
  - 把术语映射写进**术语表**，例如"Workspace 统一译成工作区"。术语表可能有几百个词条，5KB 放不下，所以不存进记忆；翻译时只注入原文里实际出现了的词条。
  - 查看每个任务的注入量。
- 助手自己要遵守的规则（写在 `prompts/memory-assistant.md`）：
  - 精简，条目之间不重复，保证每个任务都不超过 5KB；
  - 术语放进术语表，某种语言专属的规则放进带 `lang` 标记的条目；
  - **拒绝把内部信息、敏感信息写进记忆**（见下文"安全"）。
- **修改先以差异的形式展示，你确认后才保存** 🟡。记忆会影响全站的回答和翻译，改坏了代价很大。
- 条目也可以手动直接编辑。
- 和助手的对话会保留一段时间，下次可以接着聊。

## 安全

**记忆会注入公开的问答。** 访客可能通过刻意构造的提问，诱导模型把记忆复述出来，所以**记忆必须当作可能被公开的内容**：

- 后台界面上显示这条提醒；
- 助手拒绝存放密钥、内部流程、客户信息。

## 记忆变化之后

- **新的请求立即使用新记忆。**
- **已有的译文** 🟡：不自动重译，因为重译要花钱。翻译相关的条目变化后，后台提示"翻译规则已更新"，并给出重译的预估费用，由你决定重译全部还是只重译某种语言。
- **和缓存的唯一联动** 🟡：每条缓存记下生成时所用记忆的版本。"生成回答"取用的记忆变化后，旧的缓存回答不再命中，避免访客继续拿到按旧口径生成的回答。精选回答不受影响。

## 对已有设计的影响

- **站点概述**（原在 ai-guard.md）：改为记忆里自动维护的"项目概述"条目。定期任务和"手动修改后不再覆盖"的规则不变，只是存放位置和编辑入口变了。
- **回答风格**（原在 admin.md）：并入"问答口径"条目，不再单独设置。
- **翻译流程**（i18n.md）：额外注入两样东西：按上表取用的记忆；**相邻块现有的译文**，让新译的句子和周围的用词衔接一致。
- **权限**（accounts.md）：新增"AI 记忆"权限 🟡，创建账号时默认勾选。
