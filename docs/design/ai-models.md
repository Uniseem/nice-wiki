# 模型接入（草案）

> 状态：讨论中。对应决策记录 D44（取代 D7"统一走 OpenRouter"）。参考了 opencode 的提供方设计。

## 目标

- 后台有一个专门的界面，用来接入各大主流厂商的模型，包括国内厂商，也包括本地部署的模型。
- 接入的渠道和模型组成一个模型池，从池子里指定哪个模型用于"快速"、哪个用于"精确"等。

## 参考 opencode 的地方

| opencode 的做法 | 我们的对应做法 |
|---|---|
| 渠道和模型的资料来自 models.dev（开源的模型目录，MIT 许可） | 同样以 models.dev 作为内置的模型目录 |
| 每个渠道可以覆盖接口地址、密钥、请求头、超时 | 渠道配置包含同样这些项 |
| 不在目录里的服务，可以按"兼容 OpenAI 接口"手动添加 | 同样支持自定义渠道 |
| 用白名单、黑名单控制显示哪些模型 | 每个渠道勾选要启用的模型 |
| 用 `model` 和 `small_model` 区分主模型和轻量任务用的模型 | 扩展成"档位"：快速、精确、视觉、嵌入、重排 |
| 自定义智能体可以单独指定模型 | 每种任务可以单独指定模型，覆盖档位的默认值 |

## 三层结构

```
渠道（厂商 + 密钥）──包含──▶ 模型 ──放进──▶ 档位（快速 / 精确 / ……）──被用于──▶ 任务
```

### 1. 渠道

一个渠道就是"一个厂商的一组接入配置"。

| 配置项 | 说明 |
|---|---|
| 名称 | 显示用，例如"DeepSeek 官方""公司的 Azure" |
| 预设 | 从 models.dev 的渠道清单里选择，自动填好接口地址和协议；也可以选择"自定义" |
| 协议 | 见下文"支持的协议" |
| 接口地址 | 可以覆盖预设的地址，例如使用代理或中转服务 |
| 密钥 | 只能写入，保存后不再返回给前端，界面上只显示末尾几位 |
| 额外请求头 | 部分厂商或网关需要 |
| 超时 | 总超时、两个流式片段之间的最长间隔（和 opencode 一样分开设置） |
| 并发上限 | 防止后台任务把这个渠道的额度一次性用光 |
| 启用开关 | 停用后，这个渠道的模型全部不可用 |

每个渠道都有"测试连接"按钮：发一个极小的请求，显示是否成功、耗时多少。

同一个厂商可以建多个渠道，例如两个不同的密钥。

### 2. 模型

- 选好渠道后，可用的模型来自三个地方：
  - models.dev 目录里这个渠道的模型；
  - 向渠道的模型列表接口查询（大部分兼容 OpenAI 的服务都提供 `/models`）；
  - 手动输入模型 ID。
- **勾选要启用的模型**，没勾选的不会出现在后面的选择框里。
- 每个模型的资料（价格、上下文长度、能力）默认取自目录，可以手动覆盖。目录里没有的模型，需要手动填写。
- 模型的能力标签：
  - 对话
  - 看图（图片输入）
  - 结构化输出
  - 推理
  - 嵌入（生成向量）
  - 重排

  分配档位时会按能力检查。

### 3. 档位

| 档位 | 用途 | 能力要求 |
|---|---|---|
| **快速** | 前置判断、检索核查、缓存判断等量大、要求快的任务 | 对话；最好支持结构化输出 |
| **精确** | 生成最终回答、全站翻译等对质量要求高的任务 | 对话；上下文要足够长 |
| **视觉** | 生成图片、画板、视频封面的描述 | 看图。不单独设置时，使用快速档里支持看图的模型 |
| **嵌入** | 生成向量 | 嵌入 |
| **重排** | 召回结果的重排 | 重排。可以不配置，不配置时由快速档的模型代替重排 |

- **每个档位是一个有序列表**：第一个是主模型，后面的是备用模型，可以来自不同的渠道。主模型出错、超时或者被限流时，按顺序换下一个。这取代了原来依赖 OpenRouter 实现的备用模型功能。
- **分配时按能力检查**：比如把不支持看图的模型放进视觉档，界面会直接报错。
- **更换嵌入模型**意味着所有向量都要重算。界面会先显示预估费用，确认后才执行。

### 4. 任务

系统里每一种用到模型的任务，默认使用某个档位。需要时也可以单独指定模型，覆盖档位的默认值。

| 任务 | 默认档位 |
|---|---|
| 前置判断：问题分类、改写、刷流判断 | 快速 |
| 检索核查 | 快速 |
| 缓存命中判断、把缓存的回答翻译成访客语言 | 快速 |
| 生成回答 | 精确 |
| 全站翻译 | 精确 |
| 入库时补上下文 | 快速 |
| 附件描述、视频描述 | 快速 |
| 图片、画板、视频封面的描述 | 视觉 |
| 语言判断 | 快速 |
| 对话压缩 | 快速 |
| 路径名、SEO 描述、记忆里的项目概述 | 快速 |
| 记忆助手 | 精确 |
| 生成向量 | 嵌入 |
| 重排 | 重排 |

大多数情况下只需要设置好五个档位，任务那一层保持默认即可。

任务清单只在 `server/internal/aitask/` 定义一次，模型接入（每个任务用哪个档位）和长期记忆（每个任务取用哪些记忆）共用这份清单（见 [memory.md](memory.md)）。

## 支持的协议

厂商虽然很多，但接口协议只有少数几种。Go 端为每种协议各写一个适配器；具体是哪个厂商，只体现为不同的接口地址和预设。

| 协议 | 覆盖的厂商（举例） | 第一版 |
|---|---|---|
| OpenAI Chat Completions 兼容 | OpenAI、DeepSeek、Kimi、智谱、通义（百炼）、豆包（火山方舟）、MiniMax、硅基流动、OpenRouter、xAI、Groq、Ollama、LM Studio …… | ✅ |
| Anthropic Messages | Anthropic，以及提供 Anthropic 兼容接口的厂商 | ✅ |
| Google Gemini | Google AI Studio | ✅ |
| 嵌入：OpenAI `/embeddings` 兼容 | OpenAI、通义、智谱、硅基流动、OpenRouter、Ollama …… | ✅ |
| 嵌入：Gemini | Google | ✅ |
| 重排：`/rerank` 风格（Cohere、Jina 格式） | Cohere、Jina、Voyage、硅基流动、OpenRouter …… | ✅ |
| 需要特殊认证的云平台 | Amazon Bedrock（AWS 签名）、Google Vertex（服务账号）、Azure OpenAI（专用地址格式） | 以后再做 |

models.dev 用 `npm` 字段标明每个渠道该用哪个 AI SDK 的包，例如 `@ai-sdk/openai-compatible`、`@ai-sdk/anthropic`、`@ai-sdk/google`。我们用这个字段判断渠道该用哪种协议。

## 模型目录

- 编译时把 models.dev 的数据快照打进程序，保证离线也能用。
- 运行时每天从 `https://models.dev/api.json` 更新一次；后台也可以手动刷新。只是下载公开数据，不发送任何站点数据。
- 你在后台手动覆盖的资料（价格、能力等）保存在本地，优先于目录。

## 计费与花费上限

原来依赖 OpenRouter 在响应里返回实际金额。接入多个厂商之后，改为：

- 每次调用按"用量 × 单价"计算花费。单价取自目录或手动填写的值。
- 渠道在响应里返回了实际金额时（例如 OpenRouter），优先使用实际金额。
- 档位里的模型如果没有单价，界面上会给出警告：这个模型的花费无法计入每日上限。
- 仪表盘的花费可以按渠道、模型、任务分别查看。

## 结构化输出

前置判断、检索核查等任务要求模型返回固定格式的 JSON：

- 模型支持结构化输出时，直接用这个能力。
- 不支持时，在提示词里要求输出 JSON，收到后校验格式，不合格就重试一次，再不行就换备用模型。

## 权限

- **渠道的增删改、密钥：只有超管能操作**（"API key 等设置自始至终只有超管能设置"）。
- **档位和任务的模型分配：也只有超管能修改**（D53）。换模型会直接影响花费，和密钥同样对待。
- 密钥保存在 `data/config/secrets.json`，不进 git，不出现在日志和接口的返回值里。

## 初始化向导

原来要求填写 OpenRouter 密钥，现在改为"接入至少一个渠道"：
- 推荐 OpenRouter：一个密钥就能用到大部分厂商的模型，适合快速上手。
- 也可以直接接入其他厂商。

在快速档、精确档、嵌入档都设置好之前，AI 相关功能保持关闭，后台会提示还缺哪一项。
