## 页面布局

经典的文档站三栏布局，和 VitePress、GitBook 类似：

```
┌──────────────────────────────────────────────────────┐
│ 2.0 版本已发布，查看更新内容 →                      ✕   │  ← 公告横幅（可选）
├──────────────────────────────────────────────────────┤
│ 站点名称              [AI 问答]  [语言切换]  [亮/暗]    │  ← 顶栏
├────────────┬────────────────────────────┬────────────┤
│ 文档树       │ 文档标题                     │ 本页目录     │
│ ▸ 入门      │                            │ · 安装      │
│ ▾ 指南      │ 正文……                      │ · 配置      │
│   · 安装    │                            │   · 环境变量 │
│   · 配置    │                            │            │
│ ▸ 参考      │ ← 上一篇            下一篇 →  │            │
└────────────┴────────────────────────────┴────────────┘
```

- **左侧文档树**：整站的文档树，当前文档高亮，并自动展开它所在的分支。
- **右侧本页目录**：当前文档的标题大纲；滚动正文时，高亮当前读到的标题。
- **手机上**：文档树和本页目录都收进抽屉，从顶栏打开。
- **文档末尾**：显示"上一篇 / 下一篇"，按文档树的顺序排列。
- **顶栏**：AI 问答入口、语言切换、亮暗主题切换。
- **公告横幅**：后台设置文字、链接、起止时间，文字会翻译。访客关闭后，同一条公告不再显示。

文档树由 Go 渲染，每种语言渲染一份，随页面一起输出。展开、折叠以及本页目录的高亮，由页面上挂载的 Vue 组件负责。

## URL：可读路径

```
/zh/guide/install
 │   │     └── 这篇文档的路径名
 │   └──────── 父文档的路径名
 └──────────── 语言
```

- **路径名的来源**：文档第一次发布时，由模型根据标题生成英文路径名，例如"安装指南"生成 `install`。你可以手动修改。
- **所有语言共用同一个路径名**，只有语言前缀不同。
- **路径名按文档树逐级拼接。** 同一个父文档下，路径名不能重复。
- **改名或移动文档时**，旧路径自动 301 跳转到新路径。
  - 跳转表记录"旧路径 → 文档 ID"。移动父文档时，它下面所有子文档的旧路径也一并记录。
  - 跳转表存在 `data/redirects.json`，纳入 git，不会丢失。
- 站内链接本来就存的是文档 ID（见 editor.md），所以改路径不会影响站内链接，跳转表只是为了外部链接和搜索引擎。

## SEO 细节 🟡

每个页面都输出：
- `<title>` 和 SEO 描述（见 admin.md 的"文档属性"）
- Open Graph 分享信息：标题、描述、分享图
- `canonical` 标签，以及各语言版本的 `hreflang` 标签（见 i18n.md）
- JSON-LD 结构化数据：面包屑导航，帮助搜索结果显示文档的层级

站点级别：
- 每种语言一个 sitemap，外加一个总索引
- `robots.txt`

## 图片的替代文字 🟡

AI 检索本来就要为每张图片生成描述，这段描述同时用作图片默认的 `alt` 文字，并随翻译流程翻译成各种语言。这样对读屏软件、对 SEO 都有帮助，你也不用手动填写。手动填写过的 `alt` 优先使用。

## 其他页面 🟡

- 自定义的 404 页面：带文档树，以及一个 AI 提问入口，例如"没找到？问问 AI"。
- 已删除文档的 URL 返回 410（见 admin.md）。
- 页脚：版权信息、自定义链接、ICP 备案号。

## 面向 AI 爬虫 ✅

欢迎 ChatGPT、Claude 这类 AI 的爬虫抓取，并为它们提供更好读的版本。这样用户向 AI 助手问起你的产品时，能得到准确的答案。

- **每个页面都有 Markdown 版本**：在地址后面加 `.md`，例如 `/zh/guide/install.md`。HTML 页面的 `<head>` 里用 `<link rel="alternate" type="text/markdown">` 指向它。
- **`llms.txt`**：站点根目录的索引文件，按文档树列出所有文档的标题、一句话描述和 Markdown 链接。每种语言各一份（`/zh/llms.txt`、`/en/llms.txt`），根目录的 `/llms.txt` 指向它们。
- **`llms-full.txt`**：把一种语言的所有文档拼成一个文件，方便 AI 一次读完。
- `robots.txt` 明确允许主流 AI 爬虫。
- 文档页上加一个"复制为 Markdown"按钮，方便访客把整页内容粘贴给自己用的 AI 助手。🟡

因此 Go 端要多写一个渲染器：Tiptap JSON → Markdown。现在一共三个输出：HTML（公开页面）、纯文本（AI 检索和翻译）、Markdown（AI 爬虫）。画板、视频在 Markdown 里输出为图片链接加文字描述。

## 访问统计 ✅

内置简单统计，不依赖第三方服务，不使用 cookie。

- **采集方式**：页面加载后，由页面上的脚本发送一次浏览记录（`navigator.sendBeacon`）。大多数爬虫不执行脚本，天然就被排除在外；服务端再按 User-Agent 过滤一遍已知的爬虫。
- **独立访客数**：用"IP + User-Agent + 当天随机生成的盐"计算哈希，盐每天更换，第二天就无法再关联。原始 IP 不保存。这是 Plausible 这类注重隐私的统计工具采用的做法。
- **统计项**：
  - 浏览量、独立访客数
  - 热门文档，按语言区分
  - 来源网站（只记录域名）
  - 访客国家（用已有的 GeoIP 库）
  - 语言分布
- **存储**：明细保留一段时间（例如 30 天），每天汇总成按日统计的数据，汇总数据长期保存。
- **和 AI 问答联动**：在后台，把"热门文档"和"答不上来的问题"放在一起看，就知道哪些内容最需要完善。

AI 爬虫访问的 Markdown 版本单独计数，可以看出 AI 在读哪些文档。
