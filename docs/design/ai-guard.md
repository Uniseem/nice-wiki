# AI 问答防滥用（草案）

> 状态：讨论中。对应决策记录 D22。

## 要防的两类滥用

- **刷流**：短时间内大量提问、重复提问、问和站点无关的问题，目的是消耗额度或干扰服务。
- **反代**：有人把我们的问答接口包装一层，当成免费的大模型接口来用。

## 三层防线

### 第一层：人机验证（每位访客）

- 访客第一次提问前，先通过 Cloudflare Turnstile 的无感验证。大多数真人完全不需要操作。Turnstile 免费，站点不需要接入 Cloudflare 的 CDN 也能用。
- 验证通过后，访客拿到一个有时效的问答会话（签名 cookie）。问答接口只接受带有效会话的请求。
- 会话只能在真实页面里获得，直接调用接口的脚本拿不到。
- **备用方案：工作量证明** ✅（D50）。Turnstile 依赖 Cloudflare，国内部分网络访问不稳定。验证组件几秒内加载不出来时，自动改用自托管的工作量证明：浏览器在后台花一两秒算一道哈希题，正常访客几乎无感，批量脚本的成本则大幅上升。判定为可疑时提高难度。它比 Turnstile 弱，有算力的攻击者能硬算出来，所以只作备用（参考 Anubis）。

### 第二层：刷流判断（每次提问）

**程序检查**（不花钱，毫秒级）：
- 同一个 IP、同一个会话在一段时间内的提问频率；
- 和最近几个问题的重复程度：文本完全相同，或者向量高度相似；
- 请求间隔是否规律得不像真人。

**模型判断**：并入前置模型的那一次调用，不额外增加请求，也不增加延迟。

前置模型拿到以下输入：
- 记忆里的"项目概述"（见下文）
- 这个会话最近的几个问题
- 程序检查的结果

除了原来的问题分类，它还要给出一个风险判断：**正常 / 可疑 / 确定刷流**。

**和站点无关的问题**，比如"帮我写段代码""翻译这段话"，前置模型直接拒答，不会进入检索，也不会调用聪明模型。仅这一条就让反代失去了意义：每个滥用请求最多只消耗一次快速模型的调用。

### 第三层：处置

| 判断 | 处置 |
|---|---|
| 正常 | 正常回答 |
| 可疑 | 弹窗提示访客，要求完成交互式人机验证（Turnstile 的可见挑战）才能继续；之后一段时间内，每问 N 个问题再验证一次 |
| 确定刷流或反代 | 封禁这个 IP 的 AI 功能 10 分钟，到期自动恢复。页面其他部分照常可以访问 |

- **封禁的范围**：IPv4 按单个地址封禁；IPv6 按 /64 网段封禁，因为同一个用户通常拥有整个 /64 网段，换地址非常容易。
- **误伤**：公司、学校、移动网络的访客共用出口 IP，可能被连带封禁。所以封禁时间短，并且在弹窗里说明原因和恢复时间。
- 封禁记录和可疑事件在后台可以查看，也可以手动解封。

## 项目概述（原"站点概述"）

已并入长期记忆模块，成为记忆里自动维护的"项目概述"条目（见 [memory.md](memory.md)）：
- 定期任务每天更新一次；如果期间累计发布了较多文档，提前更新。内容是：这个站点是做什么的，涵盖哪些主题。
- 前置模型取用它，判断问题和站点是否相关；AI 问答窗口的开场白也取自它，例如"我可以回答关于 X 的问题"。
- 在记忆模块里手动修改后，定期任务不再覆盖它，除非重新打开自动更新。

## 获取访客的真实 IP

程序只通过反向代理对外服务（见 D23），所以必须从代理传来的请求头里读取访客的真实 IP，例如 `X-Forwarded-For`、`CF-Connecting-IP`。

**只信任配置里列出的代理地址发来的这些请求头。** 否则任何人都可以伪造请求头里的 IP，绕过封禁。

## 上限与限流 ✅

参考 OWASP 大模型十大风险的 LLM10"无节制消耗"（见 `docs/reference/`），对应决策 D50。默认值都可以在后台调整。

| 上限 | 默认值 | 超出时 |
|---|---|---|
| 单个问题的长度 | 500 字 | 直接拒绝，提示访客精简问题 |
| 每次调用模型的输出长度 | 前置模型 500 token、核查 800 token、回答 1500 token | 截断 |
| 一个问题最多拆成几个子问题 | 4 个 | 只保留前 4 个 |
| 检索员的轮数 / 工具调用次数 | 3 轮 / 5 次 | 用已有的材料作答 |
| 同一会话同时处理的问题 | 1 个 | 上一个回答完之前，新问题排队 |

**按花费限流**（可以整体关闭）：只按次数限流挡不住"少量但很贵"的请求，所以按每小时的花费累计，分两层：
- **每个会话**一个较低的上限；
- **每个 IP** 一个较高的上限（默认是会话上限的 5 倍），避免误伤共用出口 IP 的公司、学校。

超出时提示访客稍后再试，并告知恢复时间。

**长对话**由自动压缩处理，见 ai-qa.md 的"对话的自动压缩"。

**不再叠加更多的模型护栏**：护栏叠得越多，正常访客被误拦的比例越高（NeMo Guardrails 相关的经验）。保持"程序检查 + 前置模型"两层。

## 成本兜底 ✅

- **整站每日花费上限**：按每次调用的花费累计（计费方式见 ai-models.md），超出后当天暂停问答。上限在后台设置，设为 0 表示不限制。翻译、生成描述这类后台任务的花费单独统计，不占用这个上限。
- **厂商那边的额度上限**：厂商支持的话（例如 OpenRouter 可以给密钥设置额度），在厂商后台另外设置一道上限。

模型判断总会有漏判，这两条是不依赖判断准确度的成本保险。
