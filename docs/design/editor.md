# 编辑器设计（草案）

> 状态：讨论中。对应决策记录 D4、D9。

## 定位

只作为编辑器使用：交互参考思源笔记，用 Tiptap 3 实现。**不做**块引用、反向链接、嵌入块、知识图谱这类知识管理功能。

块 ID 仍然保留，它是增量翻译、AI 引用、锚点链接的基础。

## 参考思源的交互

| 交互 | 实现 |
|---|---|
| 每个块有稳定的 ID | `@tiptap/extension-unique-id` |
| 块左侧的拖拽手柄：拖动排序，点开菜单（转换类型、复制、删除） | `@tiptap/extension-drag-handle-vue-3` |
| 输入 `/` 弹出插入菜单 | `@tiptap/suggestion`，菜单界面自己写 |
| 输入 `## `、`- `、```` ``` ```` 这类 Markdown 快捷输入 | Tiptap 内置的输入规则 |
| 选中文字时弹出格式工具条 | Tiptap 的 BubbleMenu |

以上都是 MIT 许可的官方扩展（Tiptap 3.31）。

## 块类型（第一版）

每种块都要在三个地方各实现一次：
- 编辑器：Tiptap 扩展
- 公开页面：Go 渲染器输出的 HTML
- AI 和翻译：Go 提取的纯文本

| 块 | 编辑器 | 公开页面（Go） | AI 和翻译 |
|---|---|---|---|
| 段落、标题、引用、分割线 | 官方扩展 | 直接输出 | 正文 |
| 无序列表、有序列表、任务列表 | 官方扩展 | 直接输出 | 正文 |
| 提示框（信息 / 提示 / 警告 / 危险） | 自定义节点 | 带类型样式的容器 | 正文，附带类型 |
| 表格 | `@tiptap/extension-table` | 直接输出 | 按行转成文本 |
| 代码块 | `code-block-lowlight`，可选语言 | 服务端用 chroma 高亮，页面上不需要 JS 🟡 | 不翻译；AI 索引时保留 |
| 公式（行内、独立成块） | `@tiptap/extension-mathematics` + KaTeX | 输出 LaTeX 源码；只在含公式的页面加载 KaTeX，在浏览器里渲染 🟡 | LaTeX 源码 |
| 图片 | 自定义节点：上传、图注、宽度 | `<img>` 带 `srcset`，按屏幕宽度加载合适的尺寸，懒加载 | 图片单元（见 ai-qa.md） |
| 附件 | 自定义节点：文件卡片 | 下载卡片 | 附件单元 |
| 画板（Excalidraw） | 见下文 | 显示导出的 SVG | 画板里的文字 + 和图片一样生成描述 |
| 超级块（多栏） | 见下文 | CSS Grid；窄屏时改为上下排列 | 按栏的顺序展开 |
| 视频（上传 / 平台） | 见下文 | 上传的视频用 `<video>`；平台视频先显示封面，点击后才加载 | 由公开信息生成描述 + 上下两个块 |

行内格式：加粗、斜体、下划线、删除线、行内代码、高亮、链接、行内公式。

### 关于代码高亮

编辑器用 highlight.js 的规则，公开页面用 chroma，两边给关键字分出的颜色类别可能有细微差别。编辑器只有后台的人看，这点差别可以接受。两边使用同一套配色。

## 图片的多种尺寸

- 上传图片时，在浏览器里把图片压缩成几种宽度的 WebP（例如 640、1280、1920），连同原图一起上传。每个文件都按内容寻址存储。
- 公开页面通过 `srcset` 让浏览器按屏幕宽度选择合适的尺寸。
- 服务端不需要任何图片处理库。
- 动图（GIF、动态 WebP）不压缩，保留原图。

## 站内链接

文档之间的链接**存文档 ID，不存 URL**，可以带块 ID 作为锚点。渲染时再转换成当前语言的地址。这样带来两个好处：

- 文档改名、移动位置，链接不会失效。
- 英文页面里的站内链接会自动指向英文版本，不需要翻译时再去改链接。

编辑器里插入站内链接时，弹出一个文档选择器。

## 画板（Excalidraw）

- Excalidraw 是 React 组件（MIT）。后台用一个 Vue 组件把它包起来，只在打开画板时才加载 React 和 Excalidraw，不影响编辑器其他部分的加载速度。
- 在文档里显示为一张预览图，点击后进入全屏的画板编辑。
- 保存时生成两个文件，都按内容寻址存进 `assets/`：
  - 场景数据：`.excalidraw` 格式的 JSON，用来再次编辑。
  - 导出的 SVG：亮色和暗色各一份，用于公开页面显示。
- 块里只记录这些文件的 sha256。每改一次画板就产生新文件，块里的引用随之更新；旧版本保留在 git 历史里，可以找回。
- 公开页面直接显示 SVG，不加载 React。

## 超级块（多栏）

- 结构：`columns` 节点下面有 2–4 个 `column` 节点，每一栏里可以放任意块，但不能再嵌套超级块。
- 插入方式：`/` 菜单里选"两栏"、"三栏"；把块拖进某一栏。
- 进阶（以后再做）：像思源那样，把块拖到另一个块的左右边缘，自动组成多栏。
- 可以调节各栏的宽度比例，存在 `columns` 节点的属性里。

## 视频

一个"视频"组件，支持两种来源。

### 上传的视频

- 存进 `assets/`，按内容寻址，通过支持 Range 请求的接口返回（iOS 播放视频需要这个能力）。
- 服务端不转码，转码需要 ffmpeg。上传时检查格式，建议用 MP4（H.264 + AAC）或 WebM。
- 封面：上传时在浏览器里截取一帧作为封面，也可以自己上传封面图。服务端不需要处理视频。
- AI 描述由三部分组成：你填写的标题和说明、封面图的视觉描述、上下两个块。以后可以再加语音转文字。🟡

### 平台视频

支持 Bilibili、YouTube、抖音、TikTok，粘贴视频链接后自动识别。

| 平台 | 播放器 | 公开信息来源 |
|---|---|---|
| YouTube | `youtube-nocookie.com` 嵌入播放器 | oEmbed：标题、作者、封面 |
| Bilibili | `player.bilibili.com` 嵌入播放器 | 公开的视频信息接口：标题、简介、作者、时长、封面 |
| TikTok | 官方嵌入播放器 | oEmbed |
| 抖音 | 抖音开放平台的嵌入播放器 | 页面上公开的元信息 |

具体的接口和嵌入方式，实现时逐个验证。

- **每个平台做成一个"提供方"**，实现同一套接口：识别链接、生成嵌入地址、抓取公开信息。以后增加平台，只需要多写一个提供方。
- **点击后才加载播放器**：页面上先显示封面和播放按钮，访客点击后才加载平台的播放器。这样打开页面时不会加载第三方脚本和跟踪代码，页面也更快。
- **封面图下载到本地 `assets/`**：B 站等平台的图片有防盗链，直接引用会显示不出来。
- **AI 描述**：把抓到的公开信息（标题、简介、作者、时长）交给模型生成一段描述，和上下两个块一起组成一个检索单元。
- **公开信息只在插入时抓取一次**，保存在块里。抖音这类平台可能抓取失败，失败时让你手动填写标题和简介。

## 标题层级

文档标题本身是 H1，正文里的标题从 H2 开始，最多到 H4。

## 不做

- 块引用、反向链接、嵌入块
- 数据库、属性视图
- 实时协同编辑。后台人数很少，用编辑锁避免冲突（见 accounts.md）
