# 后台账号与权限（草案）

> 状态：讨论中。对应决策记录 D21、D35。

## 账号体系

```
第一次进入后台 ──▶ 注册页 ──▶ 成为超级管理员 ──▶ 初始化向导（站点名称、基准语言）──▶ 文档管理
                                │
                                ▼
                      超管新建账号：账号名 + 初始密码 + 权限
                                │
                                ▼
其他人进入后台 ──▶ 登录页（只有账号和密码）──▶ 用的是初始密码？──是──▶ 强制修改密码
                                                    │
                                                    否
                                                    ▼
                                                  进入后台
```

- **注册页只出现一次。** 系统里还没有任何账号时，访问后台显示注册页；第一个注册的人成为超级管理员。之后后台只有登录页，再也没有注册入口。
- **超管只有一个**，就是第一个注册的账号，不能删除，也不能停用。
- **账号名注册或创建后不能修改。**
- 初始化不要求配置 AI；渠道、密钥和档位在独立模型管理模块后续设置，未配置时不阻塞文档管理，见 [D55](../adr/0055-setup-without-ai.md)。
- **登录**：只输入账号和密码。

### 注册时被人抢先的风险

第一个访问后台的人就能成为超管（这是用户的选择，不加初始化码）。所以**部署后要立即自己完成注册**；或者在完成注册之前，先不要把服务端口暴露到公网。部署文档里要醒目地写明这一点。

## 密码

- **修改密码**：输入旧密码，新密码输入两遍。
- **密码要求**：至少 8 位；新密码不能和旧密码相同。不强制要求大小写、符号这类组合，这是目前主流的密码规范（NIST）的建议。
- **初始密码**：超管创建账号或重置某人的密码后，这个账号会被标记为"必须修改密码"。对方登录后只能看到修改密码的页面，改完才能进入后台。
- 密码修改后，这个账号在其他设备上的登录全部失效。
- 密码用 argon2id 哈希保存。

## 超管忘记账号或密码

- **忘记账号**：在服务器上打开 `data/config/accounts.json`，账号名是明文保存的。
- **忘记密码**：
  1. 在 `data/config/` 下新建一个文件 `reset-superadmin.txt`，内容写新密码；
  2. 程序检测到这个文件后，把超管的密码改成这个新密码，标记为"必须修改密码"，然后删除这个文件；
  3. 用新密码登录，再改成自己的密码。

能操作服务器文件的人本来就能掌控整个系统，所以这种方式不会降低安全性。

## 权限

超管创建账号时，勾选这个账号能使用哪些功能，**默认全部勾选**（共 10 项）。权限只按功能分配，不按文档范围分配。

| 权限 | 包含的操作 |
|---|---|
| 编辑文档 | 新建文档、编辑草稿、管理文档树（移动、排序、修改路径名）、上传文件 |
| 发布文档 | 发布、撤回、删除（放进回收站）、从回收站恢复、回滚到历史版本 |
| 管理译文 | 对照编辑译文、术语表、处理待复核的译文 |
| 管理语言 | 启用或停用语言（会产生翻译费用） |
| 管理资源库 | 清理没有被引用的文件 |
| 问答管理 | 查看问答记录、设置精选回答、修改回答缓存的设置 |
| AI 设置 | 防滥用设置、问答调试台、重建索引 |
| AI 记忆 | 长期记忆：编辑记忆条目、和记忆助手对话、设置各任务取用哪些记忆 |
| 站点设置 | 首页主视觉、公告横幅、页脚、logo 等 |
| 查看统计 | 仪表盘、访问统计、花费 |

**只有超管能做的事**（不能分配给别人）：
- 账号管理：新建、停用、删除账号，重置别人的密码，修改权限
- 模型渠道的增删改：接口地址、密钥（见 ai-models.md）
- 档位和任务的模型分配（D53）
- Turnstile 密钥
- 每日花费上限
- 可信代理地址
- 备份与恢复、git 远程仓库的配置
- 彻底删除（清空回收站）
- 查看操作日志
- 强制释放别人的编辑锁

## 编辑锁

- 打开一篇文档编辑时，自动获得这篇文档的编辑锁。其他人这时打开，会看到"XX 正在编辑"，只能查看，不能修改。
- 编辑器每隔一段时间向服务端报告一次"我还在编辑"。关闭页面，或者超过 2 分钟没有报告，锁自动释放。
- 长时间没有任何输入（例如 15 分钟）时，提醒编辑者；再不操作就释放锁。
- 超管可以强制释放别人的锁。被释放的一方，编辑器会变成只读并给出提示。因为编辑内容一直在自动保存，所以不会丢失。
- 锁只保存在内存里。程序重启后所有锁都会清空，这没有问题。

草稿是每篇文档一份，大家共用，不是每个人各一份。

## 操作日志

记录谁、在什么时间、做了什么，只有超管能查看：
- 发布、撤回、删除、恢复、回滚文档
- 修改设置
- 账号的新建、停用、删除，密码重置，权限修改
- 登录成功和失败

## 其他影响

- **git 提交的作者**就是执行发布的账号，版本历史里能看到每次是谁改的。
- **停用或删除账号**时，这个账号的所有登录立即失效。被删除的账号在 git 历史和操作日志里的名字保留。
- **登录保护**：同一个账号或同一个 IP 连续登录失败多次，暂时锁定一段时间。

## 存储

账号放在服务器的文件里，不放在数据库里，这样"查服务器文件"才方便：

```
data/config/               # 不纳入 git
├── config.toml            # 普通配置：监听地址、可信代理等
├── secrets.json           # 密钥：各模型渠道、Turnstile
├── accounts.json          # 账号：账号名、密码哈希、是否超管、权限、是否必须改密码、是否停用
└── reset-superadmin.txt   # 只在重置超管密码时临时存在
```

- 写文件时先写入临时文件，再替换原文件，避免写到一半时程序崩溃把文件弄坏。
- 登录会话（session）存在 SQLite 里，数据库丢了最多就是大家重新登录一次。
- `data/` 目录的位置通过启动参数或环境变量指定，其余配置都在 `data/config/` 里。这样 Docker 部署只需要挂载一个目录。
