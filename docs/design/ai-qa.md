# AI 问答设计（草案）

> 状态：讨论中。对应决策记录 D6、D10。

## 目标

访客用自然语言提问，系统只依据 wiki 的内容回答，并在回答里注明出处（精确到块）。

分工思路：快速模型负责"搜集信息"，聪明模型只阅读筛选好的材料、负责"思考和回答"。

## 用到的成熟做法

| 做法 | 解决什么问题 | 用在哪一步 |
|---|---|---|
| 混合检索（关键词 + 向量） | 向量检索擅长语义匹配，但对型号、错误码、配置项名这类精确词效果差；关键词检索正好相反 | 召回 |
| RRF（倒数排名融合） | 两路召回的分数无法直接比较，按排名合并最稳 | 召回 |
| Contextual Retrieval（Anthropic，2024） | 文本块脱离原文后缺上下文。入库时让模型给每个块补一句背景再建索引，检索失败率显著下降 | 入库 |
| 重排（rerank） | 召回结果粗糙，用专门的重排模型精排，又快又便宜 | 召回后 |
| 查询拆分 | 复杂问题拆成多个子问题，各自检索 | 前置模型 |
| 检索子代理（agentic retrieval） | 一次检索不够时，快速模型可以补充检索或展开阅读 | 快速模型 |

## 入库流程（保存文档时）

```
文档 JSON ──拆块──▶ 块表 ──组装──▶ 检索单元 ──补上下文──▶ 关键词索引 + 向量
```

### 1. 拆块

解析 Tiptap JSON，每个块记录：ID、所属文档、父块、类型、纯文本、标题路径、内容哈希。

### 2. 组装检索单元

单个段落往往太短，单独检索效果差，所以检索的单位是"检索单元"。每个单元都记录它包含哪些块的 ID，回答时仍然能精确引用到块。

| 类型 | 组成 |
|---|---|
| 文本 | 同一小节内的相邻块合并，每个单元约 300–800 字 |
| 图片 | 视觉模型生成的图片描述 + 图注 + 上一个块 + 下一个块 |
| 附件 | 模型生成的完整描述作为一个单元；内容较长的附件，再把抽出的全文切成多个单元 |

图片描述以 sha256 为键缓存。同一张图被多篇文章使用时只描述一次，但每次出现都会单独组装一个单元，因为上下文不同。

### 3. 补上下文

让快速模型读整篇文档，为每个单元写一两句背景说明（这段属于哪个产品或功能、在讲什么），拼在单元文本前面，再建索引。

同一篇文档的所有单元共享这篇文档作为输入，配合提示缓存，成本很低。

### 4. 建索引

- **关键词**：SQLite FTS5。
  - 中文有个坑：FTS5 自带的 trigram 分词要求查询词至少 3 个字，"价格""登录"这类两字词搜不到。
  - 方案：在 Go 里先把中文切成二元组（bigram）再存进去。不依赖词典，新出现的产品名也能搜到。🟡
- **向量**：embedding 以 BLOB 形式存进 SQLite，查询时在内存里暴力计算相似度。
  - 几千个单元的规模下，一次查询只需要几毫秒，不需要单独的向量数据库。
  - 规模变大后再换成 sqlite-vec。
  - 模型倾向 `qwen3-embedding`，中文表现比 `text-embedding-3-small` 好。🟡
  - 记录生成每个向量所用的模型。换模型时全部重算，这个规模下成本可以忽略。

### 5. 增量更新

每个单元都有内容哈希，保存文档时只对变化了的单元重新补上下文、重新算 embedding。

## 问答流程

```
提问 ─▶ 前置模型 ─▶ 检索员 × N（并行）─▶ 组装材料 ─▶ 聪明模型 ─▶ 流式回答（带块引用）
```

### 1. 前置模型（快速、便宜）

- 判断问题类型：闲聊、超出范围、简单、复杂。
- 复杂问题拆成若干子问题。简单问题只走一路检索。
- 多轮对话时，把追问改写成一个完整、独立的问题。

### 2. 检索员（每个子问题一个，并行执行）

1. **召回**（纯程序，毫秒级）：关键词召回和向量召回各取前若干个，用 RRF 合并，得到约 30 个候选。
2. **重排**（约几百毫秒）：用重排档的模型（例如 `cohere/rerank-v3.5`）排序，取前约 10 个。没有配置重排档时，由快速档的模型代替（见 ai-models.md）。
3. **核查**（快速模型）：阅读这些候选，挑出真正相关的；信息不够时，可以补发一次检索，或者展开阅读所在小节的全文。最多 2–3 轮。
4. **产出**：相关块 ID 列表，每个附一句为什么相关。

### 3. 组装材料（纯程序）

去重；把命中的块扩展到所在小节；按文档里的顺序排列；每段材料带上块 ID。

### 4. 聪明模型

提示词最前面注入长期记忆里"生成回答"任务取用的条目（项目概述、品牌与语气、问答口径，见 memory.md）。只阅读组装好的材料来回答，并用块 ID 标注引用。前端把引用渲染成跳转到原文对应块的链接。

材料里找不到答案时，明确告诉访客"文档里没有提到"，不要编造。

## 延迟预估

| 阶段 | 耗时 |
|---|---|
| 前置模型 | 约 0.5–1 秒 |
| 召回 + 重排 | 约 0.3 秒 |
| 快速模型核查 | 约 1–2 秒 |
| 聪明模型出第一个字 | 约 1–2 秒 |

合计约 3–5 秒后开始输出答案，期间流式展示进度。

## 规模与语言

- 规模：几百篇文章，预计几千个检索单元。内存暴力计算向量相似度绰绰有余。
- 语言：只给基准语言建索引。其他语言的提问，先由前置模型翻译成基准语言再检索；回答用访客的语言，材料优先用对应语言的译文。详见 [i18n.md](i18n.md)。

## 已确认

- 支持连续追问。前置模型结合对话历史，把追问改写成一个完整、独立的问题再检索。对话上下文需要保存（存在服务端还是浏览器，待定）。
- 命中图片时，聪明模型只看入库时生成的图片描述和上下文，不看原图。

## 界面 ✅

- **浮窗**：文档页右下角，能感知当前页面。
- **独立问答页** `/<lang>/ask`：全屏显示。首页的"问问 AI"按钮、404 页、顶栏的 AI 入口都跳到这里。
- 两边共用同一段对话：在浮窗里问了几句，点"展开"进入问答页后，对话还在。

## 交互细节 🟡

- **感知当前页面**：在某篇文档的页面上提问时，把当前文档作为检索的优先参考。访客在"安装"页面问"第二步失败了怎么办"，系统就能知道"第二步"指的是什么。
- **引用可以点击**：回答里的引用显示为小标签，点击后跳转到原文，并高亮对应的块。块的锚点格式为 `#b-<块ID>`。
- **对话保存在服务端**：防滥用和缓存都需要对话上下文，所以对话存在服务端，浏览器只保存会话 ID。刷新页面后对话还在；访客可以一键清空。对话跟问答记录使用同样的保留天数。
- **出错时的处理**：先自动切换到备用模型；仍然失败时，提示访客"暂时无法回答"，不显示技术细节。

## 问答记录与回答缓存

### 问答记录

每次问答都保存一条记录，内容包括：
- 原始问题，以及前置模型改写后的完整问题
- 访客语言
- 回答，以及回答里引用的块
- 花费、耗时、是否来自缓存

记录里不保存 IP。后台可以设置保留天数，到期自动删除。

后台可以浏览这些记录，看访客在问什么、哪些问题文档答不上来。

### 缓存在流程中的位置

```
提问 ─▶ 程序检查 ─▶ 前置模型（分类、风险判断、改写成基准语言的完整问题）
                         │
                         ▼
                    查找缓存 ──命中──▶ 返回缓存的回答（语言不同时先翻译）
                         │
                       未命中
                         ▼
                 检索员 × N ─▶ 聪明模型 ─▶ 回答，并写入记录和缓存
```

- **用前置模型改写后的问题来匹配**。这个问题已经补全了上下文，并且翻译成了基准语言，所以连续追问的问题能命中缓存，其他语言的提问也能命中。
- **匹配用的向量就是检索要用的那个向量**。没命中时直接拿去检索，所以查缓存只多花几毫秒。

### 两种命中方式（后台选择）

| 方式 | 做法 | 成本 | 风险 |
|---|---|---|---|
| 相似度阈值 | 找出最相似的缓存问题，相似度不低于阈值（可调，例如 0.92）就直接命中 | 没有额外成本 | 向量相似度分不清意思相反的问题，比如"怎么开启 X"和"怎么关闭 X"的相似度很高。所以阈值要设高一些 |
| AI 判断 | 先用一个较低的门槛（例如 0.8）选出最多 3 条候选，再交给快速模型判断其中有没有能直接回答当前问题的 | 多一次快速模型调用，但比走完整流程便宜得多 | 能避开上面的问题 |

### 缓存什么时候失效

- **超过有效期**：有效期在后台设置，例如 7 天。
- **引用的内容有变化**：缓存记录了回答引用了哪些块，以及这些块当时的内容哈希。发布文档时，凡是引用的块有变化的缓存，立即失效。
- **没有引用任何块的回答**（例如"文档中没有提到"），在任何文档发布后都失效，因为新文档可能已经补上了答案。

### 多语言

缓存以"基准语言的问题"为键，同一个问题下按语言分别保存回答。命中时，如果还没有访客语言的回答，就让快速模型把已有的回答翻译过去，再存起来供下次使用。

### 开关

关闭缓存后，仍然保存问答记录，但每次提问都走完整流程。

### 反馈与精选回答 ✅

- **回答下方放"有帮助 / 没帮助"按钮**。被点了"没帮助"的回答不进入缓存。后台据此也能找出文档的薄弱之处。
- **精选回答**：在后台挑一条问答记录，修改回答后标记为精选。精选回答不会过期，命中时优先使用。

## 防滥用

见 [ai-guard.md](ai-guard.md)。前置模型除了给问题分类，还要给出刷流风险的判断；和站点无关的问题直接拒答。
